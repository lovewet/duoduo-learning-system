# 批改分析技能（Grading & Analysis Playbook v1.0）

> 项目约定：「**作为批改分析的技能也要纳入学生学习技能**」。
> 本文件把「拿到一堆卷子/学情报告 → 出可信诊断 → 入库 → 驱动出题与视频」
> 的完整做法固化下来。配合 `diagnosis-schema.md`（输出格式）、
> `grading-feedback-loop.md`（判分闭环铁律）、`source-ingestion.md`（摄取）使用。
> 作文专项另接 `essay-grader-cn`（教学参考评分卡）与 `essay-smart-reviewer`（评语升格）。

---

## 一、先分清你拿到的是哪类材料（决定后面所有动作）

| 类型 | 典型 | 有什么 | 缺什么 | 诊断口径 |
|:--|:--|:--|:--|:--|
| **A 结构化诊断报告/错题本** | 学校导出的「错题巩固」PDF（本次三科就是） | 题干、**得分/满分、班级得分率、官方薄弱知识点表** | 学生手写答案（【错题订正】栏常空白）、标准答案、总分 | 以官方数据为骨架；错因靠知识点 + 得分/班级差 + 同族历史错题推断；**不臆测具体错答** |
| **B 手写答题卡/试卷照片** | 擦除版试卷 + 手写答题单 | 学生答案、卷面红勾 | 官方标准答案、总分 | 按 `grading-feedback-loop.md` 逐题判「对/半对/错」，判错前先读全题干规则 |
| **C 练习册 / 加练页** | 家长拍的题页 | 题目、学生笔迹 | 官方评分 | 按概念归族，答案需程序验算（Fraction/整数），不另起事实源 |
| **A+B 同场** | 本次 阶段31：先有手写答题卡，后补学校错题本 | 两边互补 | — | **B 提供学生答案，A 提供官方得分与题面**，用 `paper_qno` 对齐；A 补上的题面要回头订正 B 的初判 |

> 🔴 材料不齐时必须明写缺什么、**不编造分数**；
> 后来 A 到了，正好补齐题干，并订正了两处初判（9(1) 默写实为全对 → 错题 1441 作废；
> 作文内容初判臆测 → 按 OCR 全文改正）。**材料不全时诚实标注，比补全猜测更值钱。**

## 二、读取通道分层（按可靠性择优，不迷信 OCR）

```
① PDF 文本层（workbuddy-pdf -f md） ← 学校报告/电子卷，最可靠，优先
② 夸克扫描王官方 Agent CLI：
     yescan --scene general-ocr ← 印刷体、公式补全
     yescan --scene handwritten-ocr ← 手写，自动分 PrintedText/WrittenText
     yescan --scene question-ocr ← 题面结构化（不稳定时回退 general-ocr）
   配置：pip install yescan → yescan config set SCAN_WEBSERVICE_KEY <AI Agent 组 ClientSecret>
③ 本机离线 RapidOCR（local-ocr 技能） ← 无额度时的印刷体交叉核对，手写误识不采信
④ 原图 3–8 倍放大 + 自动对比度 + 视觉逐题核对 ← 最终裁判
```

**硬规则**：OCR 与视觉不一致时**以原图为准**。
阶段31 夸克对手写有 9 处误识（「关不胜收 / 吗上 / 亭不犹豫 / 恩渝州」等），
均回原图复核后**没有算到孩子头上**，并写进转录文件的「OCR 误识校正表」。

**夸克双额度池坑**：`/vision` 标准 API（「标准 API 通道组」 + 签名）与
AI Agent 通道（`yescan` CLI + 「Agent 通道组」 的 ClientSecret）是**两个互不相通的额度池**，
前者报 `A0211 quota exhausted` 不代表没充钱。详见 SKILL.md §6.6.5。

## 三、逐题诊断三段式（写进 `items[]`）

```
证据（evidence[]） → 归类（error_type / category_id） → 正确动作（correct_action）
```

- **证据**只写可核实事实：官方得分 6.0/14.0、班级得分率 39.5%、
  官方薄弱表「标题含义 33.33%」、OCR 复核结论、历史同族错题 ID。
- **归类**按 `three-subject-error-categories.md`：数学 M1–M4 / 英语 E1–E5 / 语文 Y1–Y3，
  英语 `error_type` 一律 `grammar`（用户硬偏好）。
- **正确动作**必须可观测：「按内容/结构/效果三段写」而不是「注意答题方法」。

**得分率的两个用法**（本次新固化）：
- `my_rate` vs `class_rate` 的**差值**决定是不是个人短板：
  YW-04《朝花夕拾》班级 77% 而孩子 62.5% → 个人记忆型短板，要练；
- `class_rate` 很低（如 MA-02 第 23 题 23.0%）说明全班都难 → 属**高难专项**，
  视频检索要走「针对性专项课」轮，且大概率无通用课，准备好靠讲。

## 四、跨学科根因归并（这是诊断最值钱的部分）

不要停在「语文错 6 题、数学错 5 题」。把逐题结论往上归一层，找**同一个动作缺陷**：

本次三科归出 5 条根因（写进 `cross_findings`，带权重，合计 1）：

| 权重 | 根因 | 跨了哪几科 | 证据 |
|--:|:--|:--|:--|
| 0.30 | 不回题干/原文做全量逐项确认 | 语/英/数 | 语文作文把导语首词当命题（第 4 次复现）、英语六选五 0/4、数学 18 题两解 |
| 0.25 | 分类讨论与多解意识 | 数 | 历史错题库已记「距离为定值只答一解」，本次 18 题仍 3/10（跨月复现） |
| 0.20 | 答题模型（三段式/分层）缺失 | 语 | 修辞赏析/句段作用/标题含义/人物形象四类同构 |
| 0.15 | 新定义四步法（读定义→设元→分段→验根） | 数 | 23 题 0/4、24 题 7/8、26 题 10/12 |
| 0.10 | 英语语篇衔接与信息转写 | 英 | 六选五 0/4、完成图表 4/10，而词汇 90%（读得懂词、读不懂篇） |

**根因必须回写出题考核**（`assessment_focus`），否则诊断就是一次性报告。见 §6.7。

## 五、入库流水线（顺序不能变）

```
① 备份 error_db.sqlite（带时间戳，放 01_错题库/ 或同目录 .bak-*）
② 按 source + item_id 查重（幂等重跑不产生第二条）
③ errors：注意 chapter / tags / resolved 三列 NOT NULL 无默认值；
   resolved 写 0，study_round 写 "1"（文本列），severity 用 emoji
④ error_category_mapping：先 DELETE 该 error_id 再 INSERT，保证幂等
⑤ diagnoses / diagnosis_items：结构化诊断主表与逐题表
⑥ mastery 联动：只更新能精确匹配 knowledge_base.point_name 的行，
   不新建脏知识点；mastery_level 是 INTEGER，别写字符串
⑦ 校验：错题数 / 映射数 / 诊断项数 / 抽样 3 条明细
```

**订正留痕**：初判被后续材料/OCR 推翻时，不物理删除，改 `status='archived'` +
写清订正原因，并同步改 `submission_items.verdict` 与 `submissions` 计数。
（阶段31 错题 1441 即按此处理。）

## 六、与作文专项技能的衔接

作文不是「一道错题」，要单独出 `essay_diagnosis` 类型的结构化诊断：

1. 用夸克 `handwritten-ocr` 转录全文 → 回放大原图逐字校对 → 出「OCR 误识校正表」；
2. 调 `essay-grader-cn` 出五维教学参考评分卡（**明确标注非学校成绩、不估分**）；
3. 调 `essay-smart-reviewer` 的规则库出评语与升格卡；
4. 升格卡按技能红线**只给方向不代写**，本回合只改一个靶点，示范半句即止；
5. 文面错别字单独成条（`error_type=spelling`），不计入立意分。

## 七、踩坑清单（每条都是真出过事的）

| 坑 | 后果 | 正确做法 |
|:--|:--|:--|
| 把学校错题本的空白【错题订正】栏当成「学生没答」 | 错因全错 | 先判断材料类型，见 §1 |
| 凭局部放大图「看着像」补写作文内容 | 阶段31 写出「父亲护他躲蛇」这种臆测 | 密集手写必须全文 OCR + 视觉复核，不补全 |
| 没读全题干规则就判错 | 9(1)「任选两句，三句皆答按前两句判分」被误判失分 | 判错前先读完整题干与限定条件 |
| PDF 文本层吞掉数学字母/公式 | 题干变成「点 表示的数是」无法诊断 | 夸克 general-ocr 补 + 原图复核 |
| 用 OCR 误识字当错别字 | 冤枉孩子 | 以原图为准，建误识校正表 |
| 官方没给总分却折算出分数 | 数据污染 | `score/full` 为 null，报告写「不估分」 |
| 只写自由文本报告 | 出题/视频/台账都读不到 | 先结构化 JSON + 入库，再渲染报告 |
| 用 `errors.chapter` 等 NOT NULL 列时不给值 | `NOT NULL constraint failed` | 显式给全必要列 |
| 把 `mastery_level` 当字符串写 | 类型污染 | 它是 INTEGER |
| 跨会话不查历史同类错题 | 漏掉「跨月复现」这个最重要的信号 | 入库前查同知识点历史记录 |
