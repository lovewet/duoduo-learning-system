# B 站学习视频推荐：算法规范与历史踩坑台账

> 本文件是 `scripts/video_recommender.py`（轻量即时入口）的规格说明，也是
> 阶段18 ~ 阶段33 期间所有关于「找什么视频、怎么核实、怎么排序、什么算好视频」
> 的要求与踩坑的完整收敛。**算法实现的每一条规则都能在 §7 台账里找到出处。**
>
> **三者的分工（别用错）**：
>
> | 角色 | 文件 | 什么时候用 |
> |:--|:--|:--|
> | 主规范 | `SKILL.md` §8「视频课推荐 v2.0」 | 定义四轮检索、可解释评分、质量分档的完整口径 |
> | 主实现 | `scripts/bili_video_engine.py --topics topics.json` | 整套讲义 / 逐题批量挂接，带审计表与全局 BV 去重 |
> | 轻量入口 | `scripts/video_recommender.py --kp ... [--hard]` | 临时查一个知识点或一道难题，命令行一问一答 |
> | 唯一护栏 | `references/video-guardrails.json` | 硬规则、偏好 UP、★保留、DROP、年级拒绝词、学科语境词、阈值 |
>
> 两个引擎**共用同一份护栏**，因此 DROP / ★保留 / 指定 UP / 年级淘汰结论一致；
> 评分公式不同（批量引擎见 §8.4 七维可解释评分，轻量入口见本文 §3 四维×质量门），
> 批量场景一律以 `SKILL.md` §8 为准，轻量入口只用于快速取 2~3 条候选。

## 1. 为什么需要一套算法

讲义和练习册里每节都要配 2~3 条视频。早期靠临场发挥，反复出问题：
给的链接点开是别的考点、BV 号是编的、搜不到就甩一个搜索词、30 分钟的课不告诉孩子看哪一段、
同一条 BV 挂到四个不相干单元。这些都不是"格式问题"，格式门禁抓不到，必须变成算法硬约束。

一句话目标：**每节配的每一条，都是当场能核实、真对得上这个考点、且已知效果最好的视频。**

## 3. 打分公式（为什么讲口诀的高播放视频排不上去）

```
base = 对口度(0~40) + 时长(0~25) + 口碑(0~20) # 0~85
讲法 = clamp(8 + 2.5×min(2,原理词) − 4×min(2,口诀词), 0, 15)
质量门 = 0.5 + 0.5 × 讲法/15 # 0.5 ~ 1.0
得分 = 100 × (base/85) × 质量门 + 偏好加权
偏好加权 = 指定 UP +8 / ★保留 +6 / 实测有效 +10（上限 100）
```

**讲法是乘性的，不是加性的**：一条"秒杀口诀"视频即便标题精准对口、播放百万，
质量门 0.5 会把总分直接砍半，进不了备选线。这就是"讲原理优先于讲口诀"的算法落地。

**对口度是硬门槛，不是分数**：标题完全没点名该知识点（`kp_hit == 0`）直接出局，
播放量、UP 名气、★保留都不能补偿。历史上"考《十五夜望月》却配《次北固山下》"
"数轴动点配找规律"就是被这条拦住的。

| 维度 | 口径 |
|:--|:--|
| 对口度 | 知识点全词 + 2-gram 在标题里的命中率；全章串讲/合集/大全 −6；年级不符 −8 |
| 时长 | 10–15 分钟 = 25 分；6–10 分 = 21；15–20 分 = 18；>20 分递减并写「只看哪段」；<6 分 = 8 |
| 口碑 | ≥10 万 = 20；≥3 万 = 15；≥1 万 = 10；≥3 千 = 6 |
| 讲法 | 原理/为什么/推导/几何意义/可视化 加分；口诀/秒杀/大招/一招 扣分 |

阈值：首选 ≥ 58，备选 ≥ 50。宁缺毋滥，不够就走兜底。

## 4. 指定 UP 优先（数学）

默认配置 `preferred_up = {"数学": "郭嘉老师数学思维"}`（公开 UP 主名，仅作示例默认值，
可改成任意你认可的 UP）。这是 阶段29 用户明确追加的长期要求「以后尽可能推荐」。

**三层保障，缺一不可：**

1. **检索**：关键词矩阵第一路永远是 `<UP 名> <考点词>`，且结果只留 `author` 精确匹配；
   用 18 个考点词 ×2 页复查过他的全部投稿，确认"有没有"再下结论。
2. **排序**：`V_RANK["首选UP"] = -1`，只要他有对口的课就永远排第一；输出标「首选」。
3. **诚实**：他没有对应课时，明写「本单元 <UP> 暂无对应课，已核过其全部投稿」，
   **不拿别家的课顶上还装作首选**。判断依据是"核实通过且标题对得上考点"的候选，
   不对症的课不算他有。

配套约束：

- 年级不符的内容不挂（八上/九：因式分解、全等、勾股、将军饮马、不等式含参等列入跳过表），
  留档防以后误捡
- 命门课 `V_PIN` 置顶：21 分钟的"变速分段专讲"不能因为"同级短的先看"被挤到最后
- 单元上限 8 条，超出挤掉最弱的，但指定 UP / ★保留 / 实测有效 / 命门课永不挤掉

## 5. 难题 / 压轴：没有通用课时的针对性检索

普通知识点找单元课就够；**必做且难/压轴的题要单独配一条逐题视频**。

`--hard --question "<题干>"` 会额外构造三条定向词：

```
<考点> 压轴 专讲
<考点> 真题 精讲 <学段>
<从题干抽取的核心方法/真题出处> 讲解
```

历史上确实存在"全站 6 组关键词都搜不到对口课"的题（数表权重分析：四个 2×2 子表和相等求总和最小）。
这种情况**如实说"没有对口视频，只能靠讲"**，并给出核心方法拆解（角格算 1 次、
边中格 2 次、中心 4 次 → 权重大的位置放小数字），不硬凑一条泛课。

**三档逐题审计**（判定依据只有标题/时长/播放/单元归属，未登录拿不到字幕）：

| 判定 | 标准 | 处理 |
|:--|:--|:--|
| 够 | 最高分 ≥65，标题明确对上核心方法 | 直接挂 |
| 勉强 | 48~65，有主方法但缺一环 | 挂上并补一句讲解 |
| 不够 | <48 或零召回，核心方法无任何覆盖 | 明说无对口课，只靠讲 |

> 审计结论**不等于内容一定讲对**：格式门禁全绿 ≠ 内容干净，人工抽查题干两头仍要做。

## 6. 覆盖度与对症门禁

- **每个考点的每个题型都要有视频**：一个 SUB 里 4 类题就要 4 类对应视频，SUB 标题按实际题型写全
- **按「题型」判对症，不按题干全文**：题干常顺带提到别的词（"一个有理数的绝对值是它本身"），
  全文匹配实测 9 处报警大半误报，改按题型后 5 处全真
- **错挂核对**：把每条视频的真实标题拉回来，与单元关键词做匹配，0 分标「可疑」交人工复核
- **全局唯一 BV 去重**：曾出现 55 条挂接只有 33 个不同 BV、同一 BV 挂到四个不相干单元
- **换题后必须重配视频**：考点从「动点」变成「动点+行程+绝对值」，视频还停在动点，孩子点开是别的
- **分 P 合集按分 P 标题定位那一集**，不写 `?p=N` 猜集数
- **>20 分钟必须写清"只看哪一段、那段讲什么"**

## 8. 红线清单（违反任一条不得交付）

1. **绝不编造 BV 号**；核实不到 → `SEARCH:精准关键词` + 时长上限 + 筛选要点
2. **没过 view 接口核实存在性/真实时长/播放量的链接不能给**
3. **不对症的一律不给**（标题没点名考点 = 出局，播放量再高也不行）
4. **指定 UP 没有对应课就明说**，不拿别家充作首选
5. **难题全站无对口课就如实说"只能靠讲"**，不硬凑泛课
6. **讲原理优先于讲口诀**；10–15 分钟最佳；>20 分钟写清只看哪段
7. **换题后必须重配视频**；每个题型至少 1 条
8. **全局 BV 去重**；年级不符不挂；分 P 不猜集数
9. **淘汰要写原因**，好视频（★ / 实测有效）永久保留、不删不换
10. 文档与代码漂移时**以代码为准**并回写文档
11. **判定依据只能是可核实的实测字段**；拿不到字幕就不得声称看过视频内容
12. **付费/大会员、下架、娱乐分区、非授课标题、缺学科语境词一律排除**，护栏以 `video-guardrails.json` 为准

## 9. 配置与使用

偏好文件 `data/video_prefs.json`（**不随仓库分发**，`.gitignore` 已排除）：

```json
{
  "preferred_up": {"数学": "郭嘉老师数学思维"},
  "star": [],
  "verified": {},
  "drop": {},
  "pin": {},
  "skip_title": {}
}
```

| 命令 | 作用 |
|:--|:--|
| `--selftest` | 不联网，验证打分/排序/门槛/审计/兜底/护栏整合/短标题回归 19 项 |
| `--offline` | 用内置样例演示全流程 |
| `--kp ... --subject 数学 --grade 七年级` | 常规推荐 |
| `--hard --question "<题干>" --topics "题型A,题型B"` | 难题定向 + 覆盖度 + 三档审计 |
| `--up "<UP 名>"` | 覆盖默认首选 UP |
| `--mark-effective BVxxx --note "..."` | 登记「实测有效」，下次直接推 |
| `--json` | 输出结构化结果，供上层编排消费 |

输出的 `dsl` 数组每行是 `VID|bvid|标题|UP|时长|理由`，可直接喂给
`scripts/lecture_dsl.py` 生成讲义里的视频卡片；`SEARCH:` 前缀会被识别成搜索按钮，
不会硬编一个可能失效的 BV。
