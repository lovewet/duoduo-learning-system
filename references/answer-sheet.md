> 讲义流水线文档的第 8 章，独立成文以便按需加载。

## 8. 作答纸规范（打印 + 拍照 + 批改）

### 8.1 四条硬规则（项目约定明确，**v14 修订**）

| 规则 | 说明 |
|---|---|
| **不含任何答案** | 只印题干与选项，不印答案、解析、**也不印框图**（框图有解算记录） |
| **题号与网页一致** | 用网页上的 `.qno`（第 N 题），**不重新编号** |
| **⚠️ 全部题目都要进纸（v14 修订）** | 不只 FILL / JUDGE，**选择题也要印**：选项前留 `○` 让学生涂黑 |
| **批改依据是拍照/扫描件** | 每道题都必须在纸上留下笔迹，否则无法批改、无法入库 |

> ⚠️ **v11 曾写「选择题不进作答纸」，v14 已推翻。**
> 用户原话：「**答题纸要把全部题目纳入进去，全部都要在答题纸上写，
> 最后以拍照的答题纸或扫描件作为批改依据并进入数据**」。
> 理由很直接：批改看的是纸，题不在纸上 = 没有笔迹 = 无法判分、无法回写错题库。
> **选择题的空间成本极低**（涂一个圈），但换来的是「一册纸 = 一次完整作答记录」。

**选择题在纸上怎么印**：`○ A．xx　○ B．xx`（按宽度装箱，见 §8.7），**不给横线**。
题干里如需写一步关键过程，学生可写在选项右侧的空白处。

### 8.2 实现要点

- 每个 `.daysec` 末尾由 JS 自动插入按钮（不用改 DSL）
- 打印用 `body.print-sheet` 类做条件切换，**不影响"打印整本讲义"**
- 行数：**FILL 9 行 / JUDGE 13 行**（够写完整过程）
- 页头：姓名 / 日期 / 用时 / 得分；页脚："— 作答结束 · 共 N 题 —"

### 8.3 批改流程（打印之后）→ 完整闭环见 §8.8

```
学生手写 → 拍照/扫描上传 → 我逐题看：
  ① 答案对不对（快速）
  ② 过程全不全（有没有跳步）
  ③ 卡在第几步（对齐错因库里的 error_pattern）
→ 更新 errors.status / practice_count / correct_streak
```

**批改话术**：不写"错了"，写"第 2 步的括号里少算了一项"。

### 8.4 ⚠️ 哪些题该进答题纸（学科判定，阶段19 血泪）

**判定标准只有一句：这道题的答案是不是「一个词 / 一个选项」？**
- 是 → 不进答题纸（选择题，选完就结束）
- 不是（要写过程、写一段话）→ **必须进**

| 学科 | 不进答题纸 | **必须进答题纸** | 实测比例 |
|:--|:--|:--|:--|
| **数学** | 判断符号、比较大小这类能心算的 | **计算题、方程、动点、应用题**（过程就是分数） | 13/22 |
| **语文** | ——（几乎没有） | **病句修改、古诗赏析、句段作用、主旨概括、手法赏析** | 应为 **12/18** |
| **英语** | 语音选择、语法选择、阅读选择 | 单词拼写、句子翻译、作文 | 0/17（全选择） |

**血泪教训**：第一版（v7）把语文 18 题里的 14 题都做成了选择题，答题纸只有 4 道语文题。
问题在于——**语文的病句、赏析、主旨，答案本身就是一段话**。做成选择题后，孩子只要"认出来"就能选对，
**但真正考的是"能不能说出为什么、能不能分条答全"**。

而他的语文失分恰恰是「答不全、不分条」（句段作用 25%、主旨 25%、表现手法 33%）。
**这必须靠手写才能练，选择题练不出来。**

**修正规则**：
- 语文的**病句修改、古诗赏析、句段作用、主旨概括、表现手法、词句赏析** —— **一律用 JUDGE（简答），不用 MC**
- 每道简答题的题干里**写明作答要求**（如"从结构和内容两方面回答，分条写"），否则孩子还是写一句话
- 简答给 **13 行**（够写 3~4 条要点）
- **测评日例外**：可保留部分选择题便于判分，但至少要保留 2 道简答

**修正后（v8）**：语文演算题 4 → **12 道**，全套 20 → **28 道**。


### 8.5 ⚠️ 作答纸必须能导出 Word（阶段19 两次踩坑）

**坑 1**：只给 `window.print()` → 用户反馈「打印按钮没法调用打印机」。
**原因**：讲义常在内嵌预览面板（iframe / WebView）打开，`window.print()` 被浏览器拦截。

**坑 2**：改成前端 `Blob` 生成 `.doc` 下载 → 用户反馈「还是没有 word 文档」。
**原因**：某些环境对 `a.download` + `Blob` 的下载也会被拦，或者下载的 `.doc` 打不开。

**最终方案：离线生成真正的 `.docx`（最可靠）**

```bash
python scripts/make_answer_docx.py 讲义.html 作答纸.docx
```

**技术实现**（`scripts/make_answer_docx.py`，**零第三方依赖**，手写 OOXML + zipfile）：
- 5 个部件：`[Content_Types].xml`、`_rels/.rels`、`word/document.xml`、
  `word/styles.xml`、`word/_rels/document.xml.rels`
- 中文字体：`<w:rFonts w:ascii="SimSun" w:eastAsia="宋体" w:hAnsi="SimSun"/>`
- 字号：`<w:sz w:val="22"/>`（11pt = 22 半磅）
- **答题横线**：空段落 + `<w:pBdr><w:bottom .../></w:pBdr>` + `w:line="520" w:lineRule="exact"`（26pt）
- **每天分页**：`<w:br w:type="page"/>`
- 页面：A4（`w:w="11906" w:h="16838"`），页边距 2cm（1134 twips）

> ⚠️ **python-docx 在本机装不上**（`No matching distribution found`），所以走手写 OOXML 路线。
> 这条路反而更可控：体积 7 KB，不依赖任何库。

**验证三步**（写完必须做）：
1. `zipfile.ZipFile()` 打开，确认 5 个部件都在
2. 用 `xml.etree.ElementTree` 逐个解析，确认 XML 合法
3. 检查 `word/document.xml` 里：段落数、横线数（`w:bottom w:val="single"` 计数）、分页数（`w:type="page"` 计数）是否与预期一致
4. 最后用 Word / WPS 实际打开看一眼

**辅助出口**（保留但不作为主方案）：
- 网页上的「下载 Word」按钮（前端 `Blob`）—— 能用就用
- 网页上的「直接打印」按钮 —— 部分环境可用

### 8.6 ⚠️ 答案册：与作答纸严格分离（阶段19 用户明确）

> 用户原话：「**最后要输出有单独的一张所有每天题目的详解和答案**」
> ⚠️ 同一次对话里用户后来又要求「**全部题目都要在答题纸上写**」——
> 两句话**不冲突**：前者说的是**答案要单独成册**，后者说的是**题面要全部进纸**。
> 旧版我把前者误读成「选择题不进作答纸」，v14 已修正（见 §8.1）。

**三份产物，职责不能混：**

| 产物 | 含什么 | 不含什么 | 给谁 |
|---|---|---|---|
| 网页讲义 | 讲解（有答案/步骤/方法/窍门）+ 练习题（**无答案**）+ 框图 | — | 学生自学 |
| 作答纸 | **全部 63 题的题面** + 填空/简答的空白横线 + 选择题的 `○` | **任何答案**、框图 | 学生手写 |
| **答案册** | 全部题目的题面 + 正确答案 + 思路 + 完整详解 | 空白横线 | 家长/老师批改 |

**三条硬规则**
1. **题面进作答纸，答案进答案册** —— 一份纸只能有其中一样，绝不混装。
   选择题也一样：**纸上有题干+选项供涂圈，答案册里有正确项与详解**。
2. **答案册是「单独一张」** —— 独立成册，不与作答纸合并，也不附在网页末尾。
3. **题号仍与网页同源** —— 答案册用 DSL 的 `dq` 计数生成「第 N 天 · 第 X 题」，与网页 `.qno` 逐题对齐。

> **自检口令**：作答纸里搜得到「答案」「解析」「故选」→ 事故；
> 答案册里出现 `w:bottom w:val="single"` 的空白横线 → 事故。

**生成命令**
```bash
python scripts/make_answer_key.py [输出基名]
# 读 _p5/day1..7.txt（DSL 源），产出 基名.docx + 基名.html
```

**为什么从 DSL 源取，不从渲染后的 HTML 取**
- 渲染 HTML 的答案区混着 `fnote`（"你第一次就答对了"等交互文案）、两段式判分的**双份选项**、`<b>` 标记
- DSL 源是**唯一真值**：答案就在倒数字段里，干净且不会被渲染改动
- 解析规则与 `lecture_dsl.py` **完全一致**（倒数字段法，因为题干里可能含 `|`）：

| 指令 | 倒数字段 | 题干 |
|---|---|---|
| `MC` | `[-1]`解析 `[-2]`思路 `[-3]`答案索引 `[-4]`选项串 `A@B@C@D` | `join([:-4])` |
| `FILL` | `[-1]`解析 `[-2]`思路 `[-3]`答案 `[-4]`占位 | `join([:-4])` |
| `JUDGE` | `[-1]`解析 `[-2]`思路 `[-3]`答案要点 | `join([:-3])` |

- 题号：每遇 `DAY` 重置为 0，每遇 MC/FILL/JUDGE +1（与 `lecture_dsl.py` 的 `dq` 同逻辑）
- 科目：由上一行 `SUB|` 的名称前缀（`数学`/`语文`/`英语`）判定

**答案册 docx 版式**
- 封面：标题 + 三科题数统计 + 使用说明 4 条
- 每天一页（`<w:br w:type="page"/>`），页头：第 N 天 · 标题 · 本日题数 · 三科分项
- 每题四段：题头（第 X 题 · 科目 · 题型）→ 题干 → 选项（正确项标 ✔）→ 三块底纹
  - 🟢 `D1FAE5`【答案】/【参考答案要点】
  - 🔵 `EFF6FF`【思路】
  - 🟡 `FEF3C7`【详解】
- 底纹写法：`<w:pPr><w:shd w:val="clear" w:color="auto" w:fill="D1FAE5"/>...`

**答案册 HTML 版式**
- 独立浅色样式，打印友好（`@media print` 里 `.qcard{page-break-inside:avoid}`）
- 顶部 sticky 打印按钮 + 警示条「本页含答案，学生做题前请先收起」
- 选择题正确项加 `.opt.ok`（绿字 + `::after` 补一个 ✔）

**交叉校验（必做）** `scripts/verify_answer_key.py`

| 项 | 查什么 |
|---|---|
| A | 答案册题号序列 vs 网页 `.qno` 逐题对齐 |
| B | 选择题正确字母 + 正确选项文本一致 |
| C | 填空/简答题答案文本一致 |
| D | 详解长度 ≥ 20 字（防漏写） |
| E | 答案不含 `___` 占位 / `TODO` / 空值 |
| F | HTML 无双重转义、题卡数 = 总题数 |

> ⚠️ **E 项的坑**：详解里**引用题干的填空下划线**（如 `"I ______ a bird"`）是**正常的**；
> 只有【答案】里出现 `_{3,}` 才是事故。校验规则必须分开写，否则误报。
> 本次实测就误报过一次（第 5 天第 6 题英语动词辨析）。

**本次实测结果**：63 题（35 选择 + 28 需写步骤），逐题比对 **63/63 通过**，0 错误 0 提示。

### 8.7 ⚠️ 作答纸版式参数：省纸 + 字号可读（阶段19 用户明确）

> 用户原话：「**答题纸要压缩一下 空白太多太浪费纸 字体太小不便于阅读，要选择合适的参数**」

**参数集中在 `scripts/dsl_source.py` 顶部** —— 作答纸与答案册都 `import` 它，**改一处三份产物同步**，不要在各脚本里写死数字。

| 参数 | 旧值 | 新值 | 理由 |
|:--|:--|:--|:--|
| 正文 `SZ_BODY` | 22（11.0pt） | **24（12.0pt）** | 用户嫌小 |
| 题号 `SZ_QNO` | 22（11.0pt） | **26（13.0pt）** | 题号要跳出来 |
| 说明 `SZ_NOTE` | 19（9.5pt） | **21（10.5pt）** | 9.5pt 太小 |
| 行距 `LINE_BODY` | 320（1.333 倍） | **330（1.375 倍）** | 略松 |
| 横线行高 `RULE_H` | 520（26pt） | **440（22pt）** | 26pt 太占地方 |
| 横线数 | FILL 9 / JUDGE 13 | **动态 4~7 行** | 写不完，纯浪费 |
| 页边距 `MARGIN_TB/LR` | 1134 / 1021（2.0/1.8cm） | **850 / 800（1.5/1.41cm）** | 边距过宽 |
| 题间距 `GAP_Q` | 80 | **60** | 收紧 |

**效果**（v11b，28 题）：答题横线 **301 → N条（-44%）**，页数约 14 → 8 页，正文 11pt → 12pt。
**v14（全部 63 题进纸）**：63 题 / 18 页（含封面+批改记录），页均利用率约 **81%**。

**核心方法：按真实页高切分，而不是「每天强制一页」（v14 大改）**

> ⚠️ **v14 踩的大坑**：v11b 的 `fit_rules()` 建立在「每天恰好占一页」的假设上。
> 全部 63 题进纸后，单天实测 **920~1683pt**，远超可用版面 **757pt**，
> 而日志仍傻乎乎地打印「→ 1 页」，利用率算出 **120%~222%**。
> **假设失效时必须换算法，不能靠调参数糊过去。**

```python
def paginate(qs, per):
    """贪心装箱：一题不跨页，装不下就整个挪到下一页。"""
    for q in qs:
        qh = est_height_pt(q, per=per)
        limit = USABLE_PT * SAFETY - (HEAD_PT if 是首页 else HEAD_CONT) + TOL_PT
        if 当前页已有题 and 已用高 + qh > limit:
            开新页
        放入当前页

def plan_day(qs):
    """取「不增加页数」的最大横线数：先按 RULE_MIN 排得最少页数 base，
       再从 RULE_MAX 往下试，第一个页数 ≤ base 的值就是要的。"""
```

好处：既不多用一张纸，又把剩余空间尽量还给了书写区（同一页数下横线越多越好写）。

**三个易错点（都踩过）**

| 坑 | 现象 | 修法 |
|:--|:--|:--|
| **`SZ_BODY / 20.0`** | 高度少算 **10 倍**，利用率永远 "8%" | `w:sz` 是**半磅**，除以 **2** 得 pt；除以 20 是把 twips 换 pt |
| **只按 `<br>` 数行** | 英语阅读原文没有 `<br>`，实际折 8~19 行，估算当 1 行 | `est_lines()` 按**视觉宽度**估算：中日韩 1.0、英文 0.55，除以每行 42 字宽 |
| **选项一律算 1 行或 N 行** | 4 个 18 字选项合计 72 字，照样折两行 | `opt_rows()` **按宽度贪心装箱**（超过 42 字宽才换行） |

> ⚠️ **`SAFETY = 0.93` 必须留**，另加 `TOL_PT = 30` 装箱容差
> （SAFETY 已留 53pt 余量，再挤 30pt 可减少「就差一点点却分到下一页」）。

**单位换算备忘**（改参数前先算清楚）
- `1pt = 20 twips`；`w:sz` 单位是**半磅**（24 = 12pt）
- A4 = `11906 × 16838` twips；可用高度 = `16838 − 上下边距×2`
- `w:line` 是 **240 分之几倍**（330 = 1.375 倍行距）
- 页边距 `cm → twips`：**×567**（1cm = 567 twips）

**⚠️ 网页端参数必须同步（`scripts/patch_head.py`）**

`00_head.html` 在构建时把 `print.css` / `print.js.html` **内联**进去了，
所以改了源文件后**必须跑 `python patch_head.py`** 重新同步，
否则网页上的「下载作答纸 / 打印」按钮仍用旧参数（本轮就踩了这个坑）。

**版式参数的四个落点**（漏一个就会出现"网页下载的与离线 docx 长得不一样"）：

| 落点 | 文件 |
|:--|:--|
| 离线 `.docx`（主方案） | `scripts/dsl_source.py` 常量 |
| 离线 `.html`（同源备份） | `scripts/make_answer_html.py`（直接读 `dsl_source`，**不**走 print.css） |
| 网页打印区 | `assets/print.css` |
| 网页下载 `.doc` | `assets/print.js.html`（内联 CSS 字符串） |
| 已构建的页头 | `00_head.html`（**需 `patch_head.py` 同步**） |

### 8.8 ⚠️ 拍照 / 扫描件闭环：批改 → 入库（阶段19 用户明确）

> 用户原话：「**最后以拍照的答题纸或扫描件作为批改依据并进入数据**」

这条要求把作答纸从「一次性耗材」升级为**数据采集入口**。缺了后半段，前面排版得再好也只是废纸。

**闭环五步**

```
① 打印作答纸（.docx 或 .html 都行）
② 学生手写 —— 每道题都要留笔迹（选择题涂 ○，填空/简答写步骤）
③ 拍照 / 扫描 —— 整册拍完，或按天拍；尽量正、尽量平、光线均匀
④ 我（AI）按纸批改 —— 逐题判「对 / 错 / 半对」，定位错在第几步
⑤ 回写四库 —— errors / mastery / knowledge_base / task_cards
```

**第 ③ 步：拍摄要求（写在作答纸封面上，别指望口头交代）**

| 要求 | 为什么 |
|:--|:--|
| 一天一张，别混拍 | 题目按天分页，混了不好定位 |
| 拍正、四角对齐 | 斜了会影响识别 |
| 字迹深的笔（蓝黑/黑） | 铅笔太浅，拍照容易丢笔画 |
| 姓名/日期栏先填 | 批改记录要按人按天归档 |

**第 ④ 步：批改判分口径（三档，不打分档就不写）**

| 档 | 判定 | 入库动作 |
|:--|:--|:--|
| ✅ 对 | 答案对且步骤完整 | `correct_streak +1`，到期日按 §记忆曲线后移 |
| ⚠️ 半对 | 答案对但跳步 / 语文答不全 | 仍记 `errors`，`error_type` 标 `步骤不完整` / `答题不全` |
| ❌ 错 | 答案错或卡住 | 记 `errors`，必须写清**错在第几步** |

**第 ⑤ 步：回写字段（对齐 §2.1 的 6 个字段）**

```
题号（第 N 天 · 第 X 题）→ subject / knowledge_point
错在第几步 → error_pattern（不要只写"算错了"）
错因归类 → error_type（13 值枚举，见 §2.2）
证据 → evidence（引用他纸上写的原话）
置信度 → confidence（高/中/低）
来源 → source = "作答纸拍照/扫描"（可回溯）
```

```
天次　　得分　　错题号（写"第几题"）　　主要问题（一句话）
第1天　______　__________________　______________________
...
```

批改完填这张表，再按「天次 → 题号 → 错因 → 知识点」批量写回错题库，并生成下一次复习任务。
**这张表就是纸面与数据库之间的对账单**，漏填 = 漏录。
