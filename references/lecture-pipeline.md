## 1. 输入解析：从 PDF 里挖三样东西

智学网报告的结构是固定的，**前 2 页是汇总，后面 20+ 页是逐题**。

### 1.1 第一样：薄弱知识点表（前 2 页）

```
[薄弱知识点分析]
知识点 | 涉及错题 | 分值 | 我的得分率 | 班级得分率
动点问题（一元一次方程的应用） | 26 | 12.0 | 薄弱（0.0%） | 36.0%
程序流程图与有理数计算 | 7 | 4.0 | 薄弱（0.0%） | 60.0%
...
[能力点分析]
能力点 | 涉及试题 | 我的状态 | 分析
```

**要提取的字段**：知识点名、分值、我的得分率、班级得分率。
**判断"薄弱"**：得分率 < 60%（报告自带标签，直接沿用）。

### 1.2 第二样：逐题错题（后面每页一道）

```
我的错题N（我的得分 X/满分 Y，班级得分率 Z%）
来源：某周定时训练 试题ID:xxx 第 N 题
[题目原文]
【考察知识点】：…
【错因分析】：□知识不完整 □认知不完善 □运算不准确 □表达不规范 □应试技巧差 □心理素质弱
```

**注意**：PDF 里的图形（程序框图、数轴、几何图）转文字时会丢，**题目里出现"如图"的地方必须自己重画**。

### 1.3 第三样：变式练习 + 标准答案（最值钱）

每道错题后面配一道【变式练习 X.1】，来自大数据题库；**报告末尾有完整的【参考答案】和【详解】**。

```
变式练习1.1
[题目]
【详解】解：= [(−1)² −(−2)] × (−3) + 4 = 3 × (−3) + 4 = −9 + 4 = −5．
【参考答案】B
```

**这是编讲义时出题的首选素材**：
- 同考点、不同数字 → 不会"记住答案"
- 有官方详解 → 解析不用自己编，准确
- 学生没做过 → 有新鲜感

**取用规则**：
| 素材 | 能不能用作练习题 |
|---|---|
| **变式练习** | ✅ 首选（同考点、有答案） |
| **新编同型题** | ✅ 次选（自己出，但要先算） |
| **原卷原题（我的错题 N）** | ❌ 不用（刚考过，容易背答案） |

### 1.4 提取脚本要点

- 用 `pdftotext -layout` 或 PyPDF2 转全文，存成 `raw_text.txt`
- 用「变式练习」「【参考答案】」「【详解】」做锚点切段
- **数学符号会乱码**：绝对值 `|a|` 常变成空格，上标会拆行 —— **凡是看不清的，用答案反推验算**，不要猜

## 2. 错因归因：三段式（证据 → 归类 → 置信度）

### 2.1 每条错题必须写全 6 个字段

| 字段 | 内容 | 反例 |
|---|---|---|
| `error_desc` | 题目 + 学生的错误结果 | ❌"这题不会" |
| `student_steps` | 学生**实际写的过程** | ❌ 留空 |
| `correct_answer` | 正确答案 | ❌ 只写"略" |
| `error_type` | 13 值之一 | ❌ 全填 concept-confusion |
| `error_pattern` | **错在第几步、为什么** | ❌"粗心" |
| `severity` | 🔴/🟡/🟢 | ❌"中"/"high" |

### 2.2 error_type 13 值（唯一合法枚举）

`concept-confusion` `calculation` `sign-error` `formula-misuse` `missing-zero` `classification` `blank` `incomplete-answer` `careless` `grammar` `spelling` `collocation` `semantic`

**初中数学高频映射**：
| 现象 | error_type |
|---|---|
| 符号错了（(−2)³ 当 +8） | `sign-error` |
| 算错了（÷分数没转乘） | `calculation` |
| 括号里只算一项 / 算式没算完 | `incomplete-answer` |
| 空白没做 | `blank` |
| 分类没穷尽（距离只写一解） | `classification` |
| 概念搞混（坐标当距离） | `concept-confusion` |

### 2.3 「错在第几步」怎么写

这是本流水线**最有价值的部分**：不是"这题错了"，而是"第 3 步错了"。

写法：`第 N 步 + 学生做的动作 + 那一步的正确规则`

示例：
```
第 1 步：把 (−2)³ 算成 +8
为什么错：负号在括号里、指数 3 是奇数 ⇒ 结果必须是负
连带：第 1 步已经是 +8，"减负变加正"这条规则就没机会用上
```

**四种典型位置**：
- `第 1 步`：起步就错（符号、公式代入）
- `第 2 步`：中间环节（括号没算全）
- `最后一步`：算到一半停了（未化简到底）
- `漏一种情况`：分类没穷尽（动点两解、方向两解）

## 3. 排期原则：按「0 分优先 + 分值权重」排，不按课本顺序

### 3.1 排序算法

```
优先级 = 是否 0% → 分值大小 → 与班级的差距
```

**血泪教训**：曾按"课本顺序"排，把一整天给"有理数乘方"，但该板块得分率其实有 75%；而真正 0% 的动点（12 分）、行程（12 分）、规律（4 分）、流程图（4 分）合计 **32 分**被漏掉。

**规则**：得分率 ≥ 70% 的板块**不单独占一天**，只在别处顺带复习。

### 3.2 每天的结构

- **三科都碰**（避免某科荒废），但**数学占一半时间**
- 数学 4 题 + 语文 2 题 + 英语 2 题 ≈ 每天 30~40 分钟
- 第 7 天做阶段测评（15 题，三科各 5 / 5 / 4）

### 3.3 7 天的叙事

每天给一个**能记住的主题名**（不是"第 3 章第 2 节"），例如：
`Day1 三个基础考点` `Day3 动点攻坚` `Day4 规律与主旨`

## 4. 讲义每节的固定骨架（八件套）

顺序不能乱，这是"能顺着读下来"的关键：

| # | 模块 | 写什么 | 长度 |
|---|---|---|---|
| 1 | **先说清楚** | 这一节到底在考什么、为什么难、要建立什么动作 | 2~3 段完整叙述 |
| 2 | **对照表** | 把抽象规则变成"什么情况 → 怎么做"的表 | 5~8 行 |
| 3 | **易错点** | 3 条以内，每条一句话 + 为什么 | 1 个 note |
| 4 | **完整演示** | 拿后面某道题的数据，从第一步走到最后一步 | 1 个 note |
| 5 | **视频** | 2~3 条候选（首选/备选/备选2）+ 时长 + 看点 | 2~3 条 VID |
| 6 | **练习题** | 标注「学情分析·变式」或「新编」 | 2~4 题 |
| 7 | （数学）**框图** | 程序框图题每题一张，见第 6 节 | FIG |
| 8 | **判分** | 两段式（错→只给思路→再试→才给答案） | 自动 |

**「先说清楚」是灵魂**：这一段决定学生读不读得下去。写法：
> 不是"这个知识点很重要"，而是"为什么你会在这里卡住"。

## 5. DSL 语法（`scripts/lecture_dsl.py`）

### 5.1 指令表

| 指令 | 格式 | 说明 |
|---|---|---|
| `DAY` | `DAY\|日号\|标题\|css类\|今日目标` | css 类：m(数学紫)/c(语文红)/e(英语青) |
| `SUB` | `SUB\|名称\|css类\|目标说明` | **只能 3 字段** |
| `LEC<<<` … `>>>` | 多行 HTML | 唯一允许写多行 HTML 的地方 |
| `LOGIC<<<` … `>>>` | 多行 HTML | **原理层**（数学思维底层逻辑），必须写在 SUB 之后、LEC 之前 |
| `FIG` | `FIG\|图标题\|路径.svg` | 读外部 SVG 内联 |
| `VID` | `VID\|BV号\|标题\|UP主\|时长\|推荐理由` | 可连续多条（候选） |
| `MC` | `MC\|题干\|A@B@C@D\|正确索引(0基)\|思路\|解析` | |
| `FILL` | `FILL\|题干\|占位\|答案\|思路\|解析` | |
| `JUDGE` | `JUDGE\|题干\|要点\|思路\|解析` | **4 段** |
| `ENDDAY` | `ENDDAY` | **每个 day 只能 1 个** |

### 5.2 原理层 LOGIC：讲「为什么是这个模型」

**背景**：LEC 讲的是「怎么做」（步骤），学生做完能模仿但换个问法仍不会。
LOGIC 补的是「为什么是这个模型」，目标是把单个知识点还原成**可迁移的思维模型**。

**铁律**：
- 位置固定在 `SUB` 之后、`LEC` 之前。**先给本质再教操作**——顺序反了会造成「记住步骤但不知道它是什么」。
- 风格：**大白话 + 类比，像老师当面讲**。不用术语开头，先给生活化的比方。
- 每块 **≤300 字**，超了重写（防讲义膨胀）。
- 门禁 **G9**：网页 `class="logic"` ≥ 7 块，且原理层内不得出现【答案】【解析】。

**四段式结构**（class 固定）：

| 段 | class | 作用 |
|---|---|---|
| 徽标 | `lbadge` | 🧠 这道题的本质 |
| 标题 | `lhead` | 本质一句话，大白话 |
| 类比 | `lrow` + `lk="打个比方"` | 生活化场景，让他「见过」这个模型 |
| 模型 | `lrow` + `lk="真本事"` | 抽象到通式，并指出**升级出口**（这个模型后面会长成什么） |
| 换问法 | `lrow` + `lk="换个问法"` | 同一模型如何回答不同问法 |
| 易错 | `lrow` + `lk="最容易栽的地方"` | **点名他实际丢分的那一条**，不是泛泛提醒 |
| 出口 | `lexit` | ⚑ 带走这一句就够了（可复述的钩子）+ em 小字注解 |

**关键设计**：「最容易栽的地方」必须接 `mingbian-error-attribution` 已定位的**第一错点**，
写他这次真实丢分的那条，而不是这一类题的所有常见错误。

**产物分布**（已验证）：网页 ✅ / 答案册 html+docx ✅（docx 取纯文本提要）/ **作答纸 ❌ 不含**（不需手写，省纸）。

**⚠️ 适用范围铁律（阶段20 复审）**：**LOGIC 只用于数学，语文与英语不加。**
理由：语英提分靠答题模板与语感积累，抽象「本质」收益低、且有概念冲突风险。
门禁 G9 现在校验「数学 7 块且**语文 LOGIC 必须为 0**」。

**⚠️ 概念准确性红线（复审发现 6 处问题，后续必查）**：

| 易错处 | 错误写法 | 正确口径 |
|---|---|---|
| **倒数 vs 数轴** | 说「相反数/绝对值/倒数三者都在数轴上看出来」 | 倒数是<b>乘法关系</b>（乘积=1），<b>不在数轴上</b>；只有大小、正负、相反数、绝对值能用数轴看 |
| **重叠公式** | 「重叠 = 甲 + 乙 − 并起来的一段」（通项与解释自相矛盾） | <b>重叠 = 甲段长 + 乙段长 − 从头到尾的总长</b>，并给算例验算 |
| **找规律的「比」** | 「先算差、再算比」当通用口诀 | <b>分母不能为 0</b>；含 0 或负数的数列要改用<b>连乘</b>，须限定条件 |
| **正负号本质** | 「正负号就是记账符号」 | 记账只是帮助理解减法的比喻，<b>正负号表示相反意义的量</b>（课本定义），不得把比喻当定义 |
| **超纲术语** | 「自变量 + 因变量」 | 七年级尚未学，用「一个量跟着另一个量变」，可提及「以后会学函数」 |
| **中英混杂** | 「出门 walking」 | 全部中文 |

**复审要点**：写完原理层必须做三件事——
① **算例验算**（每个式子自己算一遍，对不上就是错的）；② **查适用条件**（除法分母、端点、符号）；③ **对照课本定义**（比喻不能当定义）。

**⚠️ 三处真源陷阱**（改错文件会「构建成功但 logic=0」的假绿）：
1. 网页渲染器 = **技能侧** `scripts/lecture_dsl.py`（工作区的 `dsl.py` 是历史副本）
2. CSS 真源 = **`_p6/00_head.html`**（build 从 `_p6` 拼页，不是 `_p5`）
3. `dsl_source.py` 有两份，**答案册读技能侧那份**，改完必须 cp 同步

### 5.3 语文原理层（阶段20 老师反馈驱动）

**触发背景**：任课老师讲评指出语文失分主因是**「审题不够细心、只答了一半」**，且各症状指向同一病根——
**「提取失败」而非「知识缺失」**。判定依据：
- 「知识点学过但提取困难」= 存了调不出（调用环节断，不是储存环节）
- 「脱离原文不会分析」= 知识绑死在例题上，未抽象成模型
- 「段落题答题角度不全」= 没有扫描清单，靠"想起什么答什么"

**语文七节落点**：D1病句=零件没装对 · D2古诗=把感觉说出理由 · D3句段=四角度扫描 · D4主旨标题=两层(表层+深层) · D5手法=作者加工画面的工具 · D6对比=找不同→说意味 · D7测评=五类题打勾表。

**核心手法**：
- **配色区分**：`.logic.c` 红色系（语文）vs `.logic` 紫色系（数学）。渲染器用 `logic_cls` 跟随所属 `SUB` 的 css 类。
- **「带回去的一句话」**：`⚑ 带走这一句就够了` 里**引用老师原话与作业**，让原理层与课堂口径连上（例：Day7 直接呼应老师的「保底2分」和「六道赏析题」）。
- **补背提醒**：老师因课时紧未抽查的内容（如标题作用表），要在对应节显式提醒补上。

**⚠️ 口径铁律**：**任课老师的课堂口径是术语基准**（与考试评分口径一致），
讲义原理层只做结构化补充，**不得另立一套术语**，避免孩子背两套说法混淆。
遇到老师已给的方法（如赏析四步法），原理层要**说明它对应哪个底层模型**，而非另起炉灶。

### 5.4 五条铁律（违反必出错）

1. **ASCII 竖线 `|` 是字段分隔符** —— 题干里的绝对值一律写**全角 `｜`**
2. **题干不转义，选项会转义**
   - 题干里写 `&lt;` `&gt;`
   - **选项里写裸 `<` `>`**（否则变 `&amp;lt;`）
3. **一个 day 只能一个 `ENDDAY`**（多个会提前关掉 daybody）
4. **题目行必须单行** —— 多行 HTML 只能放 `LEC` 块里
5. **自出的题必须先算** —— 答案与解析不一致是本项目最高频事故

### 5.5 构建

```bash
python scripts/lecture_dsl.py day1.txt day1.html d1
cat head.html day1.html ... day7.html tail.html > 讲义.html
python scripts/verify_lecture.py 讲义.html
```

## 5A. 题型命名体系（阶段20 用户明确要求，强制）

> 用户原话：「所有的题目都要定义他的类型……语文的病句题，学生还要填写他的错误类型……
> 重新输出，答题纸也要改，也要进入技能，赏析题也要有明确的类型和定义。」

### 5A.1 为什么必须命名

不命名的坏处不是「不好看」，而是**孩子无法归因**。
卷面上一道错题，丢分原因可能是「没认出这是程序框图题」，
也可能是「认出了但不会模拟」——**前者是提取失败，后者是知识缺失，补法完全不同**。
题型标签就是把「提取失败」这一层单独拎出来显性化。

### 5A.2 注册表（唯一真源：`scripts/qtypes.py`）

- **数学 12 种**：程序框图题、动点问题、一元二次方程根的判别、勾股定理应用、相似三角形判定与性质、
  分式方程增根、实数有效数字与无理数、绝对值与数轴、乘法公式变形、统计图表分析、
  概率初步、几何证明（辅助线）
- **语文 12 种**：病句辨析题、字音字形题、古诗文默写、文学常识、名句赏析、
  表现手法题、句子排序、词语运用、修辞手法、内容概括题、标题理解题、主旨概括题
- **英语 6 种**：语法选择题、完形填空、阅读理解（细节/主旨/推断）、翻译题、写作题、词汇拼写题
- **病句 7 型**：成分残缺、句式杂糅、重复赘余、否定不当、搭配不当、两面对一面、语序不当

每种题型含四个字段：

| 字段 | 含义 | 用途 |
|---|---|---|
| `name` | 题型名 | 徽标文案 |
| `feature` | **怎么认出它**（判定特征） | 训练「提取」能力 |
| `method` | 认出后**第一步做什么**（解法动作） | 训练「调用」能力 |
| `trap` | 最容易栽在哪 | 讲义与答案册提示 |

> `feature` 与 `method` 分离是刻意的：
> **认出题型 = 提取，动手第一步 = 调用**。孩子的错误几乎总在提取层，
> 所以 `feature` 要写得能被孩子当检查清单用。

### 5A.3 标注方式（DSL 层）

标签写进**题干**，但渲染时由 `lecture_dsl.py::split_qtype()` **剥离**——
徽标单独渲染，题干保持干净。解析层 `dsl_source.py` 会抽成结构化字段：

```
<b class="qt">【题型】程序框图题</b>　题干正文……
<b class="qb">【语病清单】成分残缺｜两面对一面｜句式杂糅｜重复赘余</b>　题干正文……
```

抽取结果：`q["qtype"] = "程序框图题"`、`q["bingju"] = ["成分残缺", ...]`。

### 5A.4 四份产物必须同步（漏一处即门禁 G10 报错）

| 产物 | 呈现方式 |
|---|---|
| 讲义网页 | 题干上方 `.qtag.qt2` 题型徽标 + `.qtag.bq2` 语病徽标 |
| 答案册 html | 题头 `.tag.qt3`「题型：」+ `.tag.bq3`「语病：」 |
| 答案册 docx | 题头「第 N 题（科目 · 题型：xxx）」+ 单列「语病类型」行 |
| 作答纸 html/docx | **题型徽标直接显示**（彩色，不填空）+ 病句题**逐句语病填空栏** |

### ⚠️ 谁「自己写」、谁「直接印」—— 阶段20 用户划清界线

> 用户原话：「**语文英语数学的题型你可以直接写出来，我只是说语病类型要学生自己写。**」

| 内容 | 作答纸上怎么处理 | 为什么 |
|---|---|---|
| **题型**（程序框图题 / 病句辨析题 / 表现手法题…） | **直接印成彩色徽标** | 题型是**知识标签**，孩子看到题干本来就不一定认得出；让他自己命名会把「审题训练」变成「猜标签」，且与语病训练的目标混在一起。命名是**我们**的事，不是他的。 |
| **语病类型**（成分残缺 / 句式杂糅 / …） | **留空白让他逐句写** | 这才是考卷上真正要答的内容。圈完选项就走等于没答。 |
| **改正后的句子** | **留空白让他写** | 只写病名算半对。 |

> **不要把两者混为一谈**：「题型自填栏」是 v8.0 的设计，v11.0 已废除。
> 现在唯一需要他自己写的是**逐句语病定性表**（`.bjtab`）。

### 5A.5 病句题：语病类型是**正式作答内容**，不是勾选辅助（⚠️ 阶段20 用户纠正）

> 用户原话：「**在学生答题的时候要答每个错误的句子的语病是什么类型，这个也要作为答题的一部分，
> 不能光做完选择题就完了，这个在答题纸上、在网页的题目上要明确。**」

**之前做错的地方**：只给了 `【语病清单】` 勾选框，**可勾可跳**。
结果学生圈完选项就走，逐句病名一个没写——而"这句话是什么语病"恰恰是**考试真正要答的东西**，
选择题只是拐杖。**勾选框不能代替填空。**

**正确做法：`BJ<<<...>>>` 块（逐句语病定性表）**，紧跟在病句题行之后：

```
MC|【题型】病句辨析题 【语病清单】…　下列句子没有语病的一项是|…选项…|2|…思路…|…详解…
BJ<<<
①|通过这次研学活动，使同学们开阔了眼界|成分残缺（缺主语）|删「通过」——这次研学活动使同学们开阔了眼界
②|一个人能否养成读书习惯，关键在于他有没有恒心|没有语病 ✅（本题正确项）|不用改
③|他之所以进步的原因，是因为每天都复盘错题|句式杂糅|删「之所以」——他进步的原因，是因为每天都复盘错题
④|这次活动的参与人数比上次增加了很多|重复赘余|删「增加」或改——这次活动的参与人数比上次增加了不少
>>>
```

每行四字段：`序号|句子摘引|语病类型|改法`。**必须有 `fix`（怎么改）——只写病名算半对**，
因为考卷上要写出改后的句子。「没有语病 ✅」的句子也要列出，证明你逐句判过。

**四份产物都要有，且答案/空白必须分开**：

| 产物 | 呈现 |
|---|---|
| 讲义网页 | 题干上方**橙色答题要求条**（`.bjreq`）+ 逐句表格 `.bjtab`（每句两个输入框：语病类型 / 改正）+ `<details>` 折叠的标准答案 |
| 作答纸 html/docx | 逐句表格，**语病类型与改正两栏都是空白**（`语病类型：____　改正：____`）；【语病清单】降级为「备选（可参考）」 |
| 答案册 html/docx | **逐句标准答案表**：句号 / 原句 / 标准病名 / 标准改法（批改依据） |

**渲染实现要点**：`BJ` 块在题目之后，`lecture_dsl.py::render()` 用 `pending_q` **题块缓冲 +
`_flush()`** 处理——遇到 BJ 时把表格追加进上一题的 `qwrap`，再由后续块收口。
不要用「事后按字符串回插」的方式，`<b>` 标签收尾极易错位。

### 5A.6 语病清单必须 7 型全列 + 速查卡（阶段20 用户纠正）

> 用户原话：「语病类型备选（可参考）**要把所有语病类型列全**」

**之前错在哪**：每题只列当题出现的 3~4 种。这有两个坏处——
① **限制判断**：孩子会以为「病句只有这几种」，遇到不在清单里的（搭配不当 / 语序不当）就不敢写；
② **暗示范围**：清单即答案边界，做题时反而去「从清单里挑」而不是「看句子定病名」。

**正确做法（两层）**：

1. **【语病清单】7 型全列**（顺序固定，按「结构 → 语义 → 语序」排列，先查结构）：
   `成分残缺｜句式杂糅｜重复赘余｜否定不当｜搭配不当｜两面对一面｜语序不当`
2. **语病 7 型速查卡**：光有名字不够——**每型必须带「怎么认出它（信号）」+「怎么改」**，
   否则孩子还是不知道怎么选。唯一真源 = **`scripts/bingju_card.py`**，
   **网页 / 作答纸 docx+html / 答案册四处必须从同一份数据渲染**，不允许各写一份。

| 类型 | 识别信号 | 怎么改（短版） |
|---|---|---|
| 成分残缺 | 句子里找不到主语了 | 删介词或删「使」，或补出主语 |
| 句式杂糅 | 两套说法套在一句里 | 两套说法留一套，删掉多余的那部分 |
| 重复赘余 | 意思说了两遍 | 删掉重复强调的那部分 |
| 否定不当 | 否定词用多了或用错了 | 删掉多余的否定词 |
| 搭配不当 | 主谓或动宾搭不上 | 换掉搭不上的一方 |
| 两面对一面 | 前面两面，后面一面 | 改成前后两面一一对应 |
| 语序不当 | 谁先谁后放错了 | 按时间/地点/方式调顺序 |

> 速查卡末尾固定一句提醒：**「先看信号再定名字 —— 这七种是起点，不是限制。」**
> 这是防止孩子把清单当封闭集合的关键。

### 5A.7 打印版 docx 必须是彩色的（阶段20 用户纠正）

> 用户原话：「**word 的答题纸打印版要跟网页的答题纸一样彩色的**」

  `C_FIX=92400E` `C_HINT=B45309` `C_TIP=15803D`；底纹 `F_HEAD=FDE68A` `F_BOX=FFF7ED` `F_TIP=ECFDF5`

> ⚠️ `w:shd` 挂在 `w:rPr`（run 级字符底纹）和 `w:pPr`（段落底纹）里是**两回事**，

## 6. 程序框图规范（每题一张）

### 6.1 形状语义（不能用错）

| 形状 | SVG | 含义 |
|---|---|---|
| 平行四边形 | `<polygon>` | 输入 / 输出 |
| 矩形 | `<rect>` | 操作（计算、赋值） |
| 菱形 | `<polygon>` | 判断 |

### 6.2 必须画出来的东西

- **循环路径**：从菱形"否"回到操作框的**红色虚线**，这是学生最容易忽略的
- **逐轮标注**：右侧「解算记录」面板，写清每轮输入→输出→是否满足条件
- **判断条件的真实符号**：`y > 0` 而不是 `y &gt; 0`（转义只能一次）

### 6.3 ⚠️ 框图含答案，不能进作答纸

「解算记录」面板写着每轮结果 = 直接给答案。
**作答纸里不放框图**（用户明确要求），框图只留在网页上看。

**框图上也不要挂「演算区」面板**（阶段19 用户明确：「把网页版的这个写法去掉」）。
练习框图只保留流程结构；演算写在题目下方的作答框里即可。
附带好处：q1 的演算区矩形原本还**压住了菱形判断框**（`rect y=170` vs 菱形 `172~260`），删掉后这个视觉 bug 一并消失。

### 6.4 参数化生成

用 Python 函数生成，参数：`公式 / 输入值 / 判断条件 / 每轮记录 / 输出文字`。
模板见 `assets/figs/q1.svg` ~ `q5.svg`（5 个实例：无循环 1 个、两轮 3 个、一轮 1 个）。

### 6.5 ⚠️ 讲解可以有答案，练习题绝对不能有（阶段19 用户明确）

这是整份讲义**最容易越界**的一条线。

| 区域 | 能不能有答案 | 理由 |
|:--|:--|:--|
| **讲解区**（LEC 里的说明、对照表、演算演示、方法卡） | ✅ **应该有**：完整步骤、正确写法、窍门、为什么这么想 | 讲解的任务就是"讲清楚"，不给答案等于没讲 |
| **练习区**（题目本身、选项、**配套的图**） | ❌ **一点都不能有** | 一旦泄露，学生就不用思考了，练习失去意义 |

**踩过的坑（两次）**：
1. 程序框图右侧有一块「**解算记录**」面板，逐轮写着"第一轮 x=3 → y=−7 / 第二轮 → 33"
   —— 这等于把答案印在题旁边。
   改法走了两步，**第二步才是用户最终要的样子**：
   - 第一步（不够）→ 改成「你的演算区」空白框，只留第一轮/第二轮/输出的填空线。
     用户仍然不要：**「把网页版的这个写法去掉」**（阶段19）。
   - 第二步（最终）→ **整个面板删掉**，框图只画流程结构。
     演算本来就在题目下方的作答框里写，图上再挂一块面板是重复且别扭的。
   见 **`scripts/strip_scratch_area.py`**（一键删除 37 个元素并收紧 viewBox）。
2. 初版作答纸还把这张带答案的框图印上去了 —— **作答纸也不放图**。

**检查清单（每次出题后逐条过）**：
- [ ] 题干里有没有出现答案数字？
- [ ] **配图里有没有计算结果 / 解算过程 / 正确结论？**
- [ ] 选项里有没有暗示正确答案的标记（加粗、括号注"正确"）？
- [ ] 图注、提示语里有没有"这里应该是XX"？
- [ ] 讲义里同一道题的**讲解段**和**练习段**有没有串（讲解的答案漏到练习区）？

**正确的做法**：
- **讲解区**：用**另一组数据**演示（不与练习题数字相同），讲透方法
- **练习区**：只给结构（如框图的形状、公式、判断条件），把中间结果全部留空
- **图**：练习用的框图 → **只画流程结构**（输入框 / 操作框 / 判断框 / 输出框 + 箭头 + 循环虚线），
  判断框只写条件（`y > 0 ?`），**不挂任何"演算区 / 解算记录"面板**；
  讲解用的框图 → 可以标出每轮结果

> ⚠️ **别把「演算区」这两个概念搞混**：
> - ❌ **框图上的演算区面板** —— 用户明确要求删掉（`strip_scratch_area.py`）
> - ✅ **题目下方的作答框标题「✎ 演算区（写清每一步，考场上也要写）」** —— 这是 `lecture_dsl.py`
> 里 FILL/JUDGE 题的正常作答区，**必须保留**，学生就在这里写步骤

## 7. 两段式判分（纯 CSS，零 JS）

### 7.1 逻辑

```
① 第一次作答 → ② 错了只给「思路」，不给答案 → ③ 再试一次 → ④ 第二次后才公布答案与解析
```

### 7.2 实现

```css
.hint1,.try2,.final{display:none;}
.qt:has(.try1 input[value="no"]:checked) .hint1{display:block;} /* 答错→给思路 */
.qt:has(.try1 input[value="no"]:checked) .try2{display:block;} /* …并给第二次机会 */
.qt:has(.try1 input[value="ok"]:checked) .final{display:block;} /* 一次对→直接给答案 */
.qt:has(.try2 input:checked) .final{display:block;} /* 二次后→公布答案 */
```

### 7.3 设计意图

这是整个讲义的核心机制，**不能为了省事去掉**。

### 5A.11 语音题：划线必须划在**解析所讲的那个音素**上（⚠️ 阶段20 实测踩坑）

**三道题同时出错，全库体检才发现**：

| 题 | 解析讲什么 | 划线实际在哪 | 后果 |
|---|---|---|---|
| Day1 第8题 | th 清浊 | `th<u>i</u>nk / th<u>i</u>s / th<u>a</u>t / th<u>e</u>se` → 划在 **i/a/i/e 元音**上 | 孩子按题面找不到唯一答案，留空 |
| Day2 第7题 | ur/ir 元音 | `surpr<u>i</u>sed` → 只有这一个划在 **i** 上，其余三个划 ur | 考的是元音，划线却不一致 |
| Day7 第12题 | th 清浊 | 四个词分别划在 **i/a/i/e** | 同 Day1 第8题 |

**根子**：出题时凭语感写了解析（考什么音），但 `<u>` 划线是**随手加的**，
没跟解析对齐。**两者是同一条知识点的两个表达，必须一起设计。**

**规范**：
- **解析讲什么音素，四个选项就全部划在那个音素上**，一个都不能漏、不能错位
- 例：考 th → `<u>th</u>ink` / `<u>th</u>is` / `<u>th</u>at` / `<u>th</u>ese`（**不是** `th<u>i</u>nk`）
- 考 ch → `wat<u>ch</u>` / `<u>ch</u>air` / `<u>ch</u>emistry` / `<u>ch</u>ina`
- 考 ur → `n<u>ur</u>se` / `s<u>ur</u>prised` / `Th<u>ur</u>sday` / `hamb<u>ur</u>ger`
- 若某个词里**没有**目标音素（考重音、元音升降等），**这题就不能用"划线不同项"的题型**，
  要改成别的题型或换词

**体检脚本**（改完题必跑）：
```python
import dsl_source as D, re
bad = 0
for d in D.load_days():
    for q in d["qs"]:
        if "语音" not in q.get("qtype", ""): continue
        parts = [(re.findall(r"<u>(.*?)</u>", o) or [""])[0] for o in q["opts"]]
        ok = all(parts) and len(set(parts)) == 1
        bad += (not ok)
        print("Day%d 第%d题 %s 划线=%s" % (d["n"], q["no"], "✅" if ok else "❌", set(parts)))
```

### 5A.12 门禁 G12

- 网页 / 作答纸 html / 作答纸 docx 三处都要有 7 型速查卡
- **作答纸 docx 与答案册 docx 必须彩色**：`<w:color>` 与 `w:fill` 各 ≥ 50 处

### 5A.13 主观题必须有「答题公式」—— 教了怎么想，还要告诉**写成什么句式**（阶段21 用户新增）

**需求原话**：「今天给学生出的语文练习题要有答题模式公式说明」

**为什么这条必须单独立门禁**：Day1 批改暴露过一个隐蔽的丢分点——
孩子**知道该写情感**，却把答案写成了一句流水话。原因是讲义只教了
「三步动作」（怎么想），**没告诉他答案该长什么样**。
阅卷是**按点给分**的，句子结构不对，四格答案只能对上零点几格。

> **「怎么想」和「写成什么样」是两件事，缺一个都会丢分。**
> 前者对应 LEC 层的动作，后者对应本节的答题公式。

#### 唯一真源：`scripts/answer_formula.py`

每种**主观题**题型一条公式，四字段：

| 字段 | 作用 | 例（古诗鉴赏题） |
|:--|:--|:--|
| `formula` | 公式骨架，直接印在题干上方 | 情感 + 手法 + 内容 + 效果 |
| `parts` | 每一格**要写什么**，照抄就能填满 | 情感→「一个词加四字」；手法→「先点名：拟人/比喻/对比…」 |

| `tip` | 这类题最容易漏的那一格（仅答案册显示） | 「四个点缺一个扣一分」 |

已注册 **8 条**：古诗鉴赏 / 炼字赏析 / 表现手法 / 句段作用 / 标题含义 /
主旨概括 / 文言实词 / 病句辨析。

### 5A.14 数学题必须有**正式书写规范** + 西文必须用**印刷体**（阶段21 用户新增）

#### 一、数学书写规范（门禁 G16）

**根子**：Day1 四处跳步，追到底层是——**作答纸只给了 5 条空白横线，
没有任何书写规范**。孩子不知道分数该怎么写、方程怎么列、结果要不要带单位，
于是能省就省，跳步就成了默认动作。

**唯一真源：`scripts/math_format.py`**，两块内容：

| 块 | 内容 | 印在哪 |
|:--|:--|:--|
| **十条规范**（`RULES`） | ① 分式不写斜杠 ② 分数线平长居中 ③ 方程必写「解：」④ 一行一步、等号对齐 ⑤ 代入单独写一行 ⑥ 结果单独一行、用最简分数 ⑦ 带分数写法 ⑧ **单位写在最后** ⑨ 应用题必写「答：」 ⑩ 草稿也要标号 | **每天数学部分前印一次**（彩色表格，靛蓝 `3730A3`） |

已注册 **9 类**：数轴辨析 / 有理数加减 / 程序框图 / 动点 / 行程 / 找规律 /
新定义 / 规律应用 / 比例应用。**新出数学题型时必须同步注册**，否则 G16 检不出。

**为什么「必写清单」比「十条规范」更重要**：十条是通用要求，
必写清单是**针对这道题**的具体动作（例：数轴题必须写「先列一行 a<0，b<0，|a|<|b|」）。
**这正是治跳步的靶点** —— 告诉他该写哪几行，而不是泛泛地"要写步骤"。

**答案册侧同样要印**（标题「判分依据 · 本题必须写出的几行」）：
判分时逐行对，缺一行扣一分，与批改闭环对齐。

#### 二、西文必须用印刷体（门禁 G17）

**踩坑根子**：`ascii/hAnsi` 全用了 **SimSun（宋体）**。
宋体的西文字形是**等宽衬线体**：`n`/`m` 挤在一起、`l` 与 `I` 难分辨、
`b` 与 `6` 易看错 —— **语音辨析题首当其冲**（考的就是听辨与形近）。

**正确设定**（三处产物统一）：

| 产物 | 设定 |
|:--|:--|
| docx | `w:ascii="Times New Roman" w:eastAsia="宋体" w:hAnsi="Times New Roman" w:cs="Times New Roman"` + `<w:kern w:val="2"/>` |
| 网页讲义 | `font-family:"宋体",SimSun,"Times New Roman"` + `font-feature-settings:"liga" 1,"kern" 1` |
| 作答纸/答案册 html | 同上，`Times New Roman` 放在 `SimSun` **之后**（西文回落用） |

> ⚠️ **顺序不能反**：`Times New Roman` 必须放在中文字体**后面**，
> 否则中文会被西文字体接管（`eastAsia` 另设才稳）。
> `liga` 开启后 `fi` `fl` 会合成连字，更像正式印刷物。

#### 三、附带的门禁：markdown 星号零残留（阶段21 实测）

已在三处渲染路径加清洗：
- `lecture_dsl.py::split_qtype()` + `_md()`（题干与思路提示）
- `make_answer_html.py::rich()`（题干与选项）

> 报出来的现象是**静默替换成 `\x01`**。改这类正则一律用 `lambda m: m.group(1)`。

### 5A.15 分数必须是**真分数竖式**，不能是斜杠（阶段21 用户指出）

需求原话：「`(m + n)/2025` 分数仍然是这样没有改过来，**全面修改**」

#### 为什么这是必须改的（不是美化，是一致性问题）

§5A.14 规范第①条教孩子「分式写成分数形式，**不能写成斜杠**」。
但**题干、解析、答案里全是斜杠** —— 规范卡教孩子别写斜杠，
题目自己却满篇斜杠，孩子照着题面抄，写出来的必然是斜杠。
> **规范必须从题面开始落地，否则规范只是一句空话。**

#### 实现：标记 + 三处渲染

**转换器 `scripts/fix_fractions.py`**（唯一真源，幂等，有 dry-run）：

```bash
python fix_fractions.py # dry-run，只报告命中
python fix_fractions.py --apply # 落盘
```

命中后转成标记：
```
<span class='fr'><span class='nu'>分子</span><span class='de'>分母</span></span>
```

> ⚠️ **标签用单引号**（`class='fr'`）—— 双引号会与 Python 双引号字符串冲突，
> 批量转换时会把 `math_format.py` 直接写成语法错误（本轮踩过）。

**判定哪些斜杠该改**（**误改比漏改更糟**）：

| 改（真分数） | 不改（斜杠的正常用法） |
|:--|:--|
| `3/2` `−11/2` `117/4` `(m + n)/2025` `16/3` `53/30` | `4/8 分`（得分）`d/f/l/m/n/s/p`（元音组合）`ur / er / ir`（语法术语）`Day 2 / 6` |

判定规则：**分母必须以数字开头**（这一条就排除了 `d/f`、`ur/er`）+ 长度 ≤ 4 +
前后不是字母数字 + 得分语境排除。

**渲染三处**：

| 产物 | 实现 |
|:--|:--|
| 网页 | CSS `.fr{display:inline-flex;flex-direction:column}` + `.nu` 带 `border-bottom` |
| docx | `frac_runs()`：分子 `<w:position w:val="10"/>`、分母 `-8`、中间一条短下划线当分数线 |

**五处产物都要放行标记**（否则会被转义 / 被 `to_lines` 剥掉）：
`lecture_dsl.rich()`、`make_answer_html.rich()`、
`make_answer_docx.html_runs()` + `make_answer_key.shade_para()`、
`dsl_source.to_lines()`（改用 `frac_render.to_lines_keep_frac`，
**剥标签前先占位保护**）。

### 5A.16 必须用**真数学排版**，不能用 CSS / 手工模拟（阶段21 用户纠正）

需求原话：「要渲染成**真正的数学的写法**」

#### 前两轮的做法为什么都不合格

| 做法 | 问题 |
|:--|:--|
| `<w:position w:val="10"/>` 升降字号 + 下划线当分数线 | 分数线是**下划线**不是分数线；分子分母**各自靠左**不居中；长度随文字漂移；不能整体缩放 |
| CSS `display:flex` + `border-bottom` | 同上，且不是数学排版，是 hack |
| Unicode 分数斜线 `⁄`（U+2044） | 仍是斜杠，只是细一点；Word 不支持竖排 |

#### 正确做法：两端各用各自的标准

| 产物 | 标准 | 关键标记 |
|:--|:--|:--|
| **docx** | **OMML**（Office Math Markup Language）= Word「插入 → 公式」生成的原生公式对象 | `<m:oMath><m:f><m:num>…</m:num><m:den>…</m:den></m:f></m:oMath>` |
| **网页** | **MathML**（W3C 标准，Chrome/Firefox/Safari 全原生支持） | `<math><mfrac><mn>3</mn><mn>2</mn></mfrac></math>` |

**两个脚本是唯一真源**：
- `scripts/omml_math.py` —— docx 侧。覆盖 `frac`/`sqrt`/`sup`/`sub`/`delim`，
  **变量自动斜体、数字与运算符正立**（教材体例）。字体 `Cambria Math`。
- `scripts/mathml_render.py` —— 网页侧。同样的元素集，
  另提供 `upgrade()` 把旧的 `<span class="fr">` 标记**就地升级**为 MathML。

> ⚠️ **docx 根元素必须声明 OMML 命名空间**，否则 Word 拒绝打开：
> `xmlns:m="http://schemas.openxmlformats.org/officeDocument/2006/math"`

#### 三条铁律（写进 `lecture-pipeline.md` §5A.16）

1. **题面、解析、答案一律用真排版**，不出现 `3/2` 这样的斜杠（得分、元音组合除外）。
2. **规范是出题侧的，不是答题侧的** —— 见下条 G16。
3. **新增数学元素先查两个脚本**有没有，没有就加，不要临时用字符凑。

### 5A.20 OMML 必须覆盖**指数与下标**，不能只做分数（阶段21 用户）

需求原话：「**该是分数要是分数，该是指数要是指数，该是下标要是下标**」

我第一版 `omml_math.py` **只做了分数和根号**，`(a + b)²` 里的 `²`
仍是普通 Unicode 字符——**不是 Word 上标**。四种元素现已全覆盖：

| 元素 | OMML | 识别写法 |
|:--|:--|:--|
| 分数 | `<m:f><m:num>…</m:num><m:den>…</m:den></m:f>` | `3/2`、`(m+n)/2025` |
| 根号 | `<m:rad>`（自带覆盖横） | `√25`、`√(a²+b²)` |
| **上标** | `<m:sSup><m:e>底</m:e><m:sup>幂</m:sup></m:sSup>` | `a²`、`m²⁰²⁵` |
| **下标** | `<m:sSub><m:e>底</m:e><m:sub>脚</m:sub></m:sSub>` | `x₁`、`a₂` |

- Unicode 上标字符要先**映射回普通数字**再放进 `m:sup`
  （`SUP_MAP = {"²":"2", …}`），否则 Word 里显示成方块。
- **根号内要递归编译**（`√(a²+b²)` 里的上标也得是公式）。

### 5A.21 五份产物题号必须**一一对应**（阶段21 用户要求 + 门禁 G19）

需求原话：「你的**题目要跟网页版一一对应**，你再重新检查，
**这个检查也要进入技能**」

#### 为什么这是最要命的一道门禁

题号是**跨产物的唯一锚点**。孩子手上是纸（作答纸 docx），
想看讲解是网页（讲义）。两边对不上就是**灾难**——
他做第 5 题，网页讲的却是第 4 题；或者纸上有 10 题、网页只有 8 题。
**答案错了能改，题号错了孩子整套都学歪。**

#### 校什么：五份产物两两比对

| 产物 | 题号来源标记 |
|:--|:--|
| 网页讲义 html | `<div class="qno">第 N 题</div>` |
| 答案册 docx | `第 N 题（科目 · 题型：xxx）` |
| 答案册 html | `<span class="qno">第 N 题</span>` |
| 作答纸 docx | `第 N 题（科目 · 选择题）` |
| 作答纸 html | `<div class="qh">第 N 题（…）</div>` |

比对三件事：① **题号集合完全相同**（不多不少、顺序一致）
② **每天题数一致** ③ **科目标注不错位**。

```bash
python verify_alignment.py --root <工作区>
```

#### 🔴 本脚本自身踩过的 4 个坑（写提取器时务必避免）

1. **`sorted()` 取最新版本 → 拿到旧文件**。版本号是字符串，
   `'v9' > 'v43'`（字典序）！一度拿 v9 去校验 v43 的产物，
   报出一堆「题目缺失」的假警报。**必须按数字排序**：
   ```python
   max(cands, key=lambda p: int(re.search(r'_v(\d+)\.html$', p).group(1)))
   ```
2. **分天不能用 `t.find('day3')`** —— 讲义页顶部有导航目录，
   `find` 命中导航而非正文，每天都被截成同一段、末尾题看起来「缺失」。
   **必须收集所有位置后按位置顺序切片**。
3. **天标题不能全文扫 `第 N 天`** —— 题目正文里就有例句
   「『第 20 天有多少』」（找规律题），会造出一个假的「第 20 天」，
   那天整段题号丢失。**必须锚定标题标记** `<div class="dnum">第 N 天</div>`。
4. **讲义的 dnum 用英文 `DAY 2`** —— 真实结构是
   `<div class="daysec" id="day2"><div class="dayhead m"><div class="dnum">DAY 2</div>`，
   按 `'<div class="daysec" id="day2">'` 精确串匹配会失败并静默回退。
   **只锚 `id="dayN"`，不要求紧跟 `>`。**

> 💡 **教训**：这 4 个坑的表现都是「误报不一致」——
> 而**误报会让人去改本来正确的产物**。
> 所以校验脚本出错误报时，**先怀疑脚本，再怀疑产物**：
> 打印各产物题数与 DSL 源题数三方对照，确认是谁错。

### 5A.22 MathML `<mfrac>` 必须**恰好 2 个孩子**（阶段21 用户抓到的真 bug）

需求原话：「第三题数学题，`2025` 在网页里是它的**指数**而不是分母，
为啥答题纸这个一直是错的」

#### 症状与根因

网页上 `(m+n)/2025` 渲染成了 `(m+n)^2025` 的样子（2025 跑到右上角）。
查出来的 XML：

```xml
<mfrac><mi>m</mi><mo>+</mo><mi>n</mi><mn>2025</mn></mfrac> ← 4 个孩子，错
```

**MathML 规范：`<mfrac>` 只能有 2 个子元素（分子、分母）。**
给了 4 个，浏览器只能瞎猜——把第一个当分子，剩下的按上标处理，
于是 `2025` 变成了"指数"。

**两处错因，都要修**：

1. **分子没包成一个孩子**：`_plain("(m + n)")` 返回多个并列的
   `<mi>/<mo>`，直接塞进 `<mfrac>` 就变成多个孩子。
   → 分子分母各自用 `<mrow>` 包起来（`_wrap()`）。
2. **连续数字被逐字符拆开**：`2025` → `<mn>2</mn><mn>0</mn><mn>2</mn><mn>5</mn>`。
   → `_plain()` 里**连续数字必须合并成一个 `<mn>`**。

#### 为什么 docx 是对的、网页是错的

| 侧 | 结构 | 是否合法 |
|:--|:--|:--|
| docx OMML | `<m:f><m:num>…</m:num><m:den>…</m:den></m:f>` | ✅ `m:num`/`m:den` 是**容器**，可含多个 run |
| 网页 MathML | `<mfrac>…</mfrac>` | ❌ 严格要求**恰好 2 个**直接孩子 |

> **同一个语义（分数），两种标准的严格程度不同。**
> OMML 容错、MathML 不容错 —— 所以 docx 一直是对的，网页一直错，
> 而因为孩子手里拿的是纸，这个 bug 藏了很久。

#### 另一处连带修的：分子前缀被吃掉

`n(n+1)/2` 原来渲染成 `n × (n+1)/2`（分子丢了前缀 `n`）。
正则从 `\(([^()]{1,20})\)` 改成 `([A-Za-z0-9]*\([^()]{1,20}\))`，
让**紧邻括号前的字母也算进分子**。

⚠️ 改完注意：group(1) 已含括号，**不能再 `fenced()` 包一层**，
否则渲染成 `((m+n))` 双括号（实测踩过）。

#### 门禁 G20（`check_fracs.py`）

逐个数每个 `<mfrac>` / `<m:f>`，判定两条真错误：
1. **结构**：`<mfrac>` 孩子数必须 == 2
2. **分母非空**

> ⚠️ **不要**要求"产物必须包含 DSL 里所有分数" ——
> 作答纸只印题干、答案册印全部，内容本来不同。
> 强制包含会造成大量误报（实测：一次报 54 处假错误）。





### 5A.23 裸 Unicode 上标必须渲染成真指数（阶段21 用户追问后补齐）

用户追问：「第三题 `2025` 我记得之前是 `m+n` 的**指数**，现在怎么改成了分母，
检查一下是否是这样的」

#### 先回答：**原题从一开始就是分母，没被改错**

四份独立证据（都在我动手之前）：

| 来源 | 时间 | 第 3 题写法 |
|:--|:--|:--|
| `_p5_backup_before_logic_audit/day2.txt` | 09:09（最早） | `(m + n)/2025` |
| `_p5_backup_before_qtype/day2.txt` | 11:41 | `(m + n)/2025` |
| `_p5_backup_before_fraction/day2.txt` | 19:22 | `(m + n)/2025` |
| `上云包/…_v13.html` | 早期网页 | `(m + n)/2025` |

解析第⑤步也写得很明确：
```
⑤ 原式 = 0/2025 − 1 + 121/4 = −1 + 121/4 = 117/4
易错点：m+n = 0 这一项直接消掉，不用真去除 ← 「去除」= 除法
```

> **「指数」印象的两个来源**：
> ① 之前 `<mfrac>` 4 孩子的渲染 bug，让 2025 跑到右上角，看着像指数；
> ② **第 4 题里真有 `m²⁰²⁵`**（指数考点），两题相邻极易混淆。

#### 但追问暴露了一个真漏洞：裸上标没渲染

`m²⁰²⁵`、`(a+b)²`、`3n²` 里的 `²³⁰⁴…` 是 **Unicode 上标字符**，
之前两条渲染路径都**只认分数标记**，这些字符原样印出去——
**看着是上标，实际是个普通字符**，不是真正的数学指数。

| 侧 | 修法 |
|:--|:--|
| 网页 | `mathml_render.upgrade_sup()`：切出**文本节点**再替换成 `<msup>`；`<style>/<script>` 整块占位保护 |
| docx | `omml_math.mixed()` 的 MATHY 正则，上标类从 `[⁰¹²³⁴⁵⁶⁷⁸⁹]` 改成 **`+`** |

> ⚠️ **docx 那个 `+` 是必须的**：不加只能匹配一个字符，
> `m²⁰²⁵` 会变成 `m²` + 残留 `⁰²⁵`（实测：答案册残留 3 个）。

> ⚠️ **网页必须按文本节点替换**，不能对整份 HTML 正则替换 ——
> 会改坏 `<style>` 里的 `content:"²"`。

#### 门禁 G20 扩展

`check_fracs.py` 增加判定：**产物里裸 Unicode 上标（`⁰¹²³⁴⁵⁶⁷⁸⁹`）必须为 0**。
残留 > 0 即说明没渲染成真指数。

#### 连带修的：答案册选项走了纯文本

答案册 docx 的选项（`A．3n² + 3n + 1`）原用 `M.para()` 纯文本渲染，
绕过了 OMML → 残留 3 个裸上标。已改走 `M.html_runs()`。

> **教训**：一个产物里可能有**多条渲染路径**（题干 / 选项 / 答案 / 解析 / 表格），
> 只改一条会漏。**验收必须数全产物字符，不能只看某一处**。

### 5A.27 🔴 DSL 里数学绝对值**必须用全角 ｜**（切坏字段的血案）

**事故**：给 Day3 加原卷题时，解析里写了半角 `|a|`、`|x+2|`。
而 **DSL 用半角 `|` 分隔字段** —— 这些竖线被当成分隔符，
字段数从 6 变成 15~25，整个 Day3 解析直接崩：

```
ValueError: invalid literal for int() with base 10:
' = 0，<b>0 不是正数</b>；<br>② <b>对</b>：绝对值最小是 0…'
```

**项目既有约定**：`｜a｜` 用**全角 U+FF5C**（Day2 等所有存量题都这样写）。

#### 两条必须遵守的操作纪律

1. **写题库题时，数学表达式一律 `｜`**：
   `｜a｜`、`｜x + 2｜`、`｜a − b｜ = a − b`
2. **拼 Python 字符串时用 `@@` 占位，最后统一替换**：
   直接在 f-string / 拼接里写全角竖线，很容易和拼接语法冲突
   （本次为此连踩两次 `SyntaxError`）。做法：
   ```python
   content = "... @@a@@ ≥ 0 ... @@x − 2@@ ..."
   content = content.replace("@@", "｜")
   ```
3. **写完必须验字段数**：`new.count("|") + 1 == 6`（FILL/MC 都是 6 段）

> **验收口诀**：字段数不对 = 内容里有半角竖线。
> 不要去看报错栈，先数 `|`。

### 5A.28 视频必须**覆盖当天每个考点的题型**（阶段21 用户：尤其数学）

### 5A.32 网页上标用 `<sup>`，不要用 MathML `<msup>`（阶段22）

#### 症状
Day3 第2题 `(b − 10)² = 0` 在页面上显示成 `(b − 10)2` —— **上标丢了**。

#### 根因
`upgrade_sup()` 把 `)²` 转成 MathML：
```html
<msup><mo>)</mo><mn>2</mn></msup>
```
MathML **只在支持它的浏览器里正常渲染**。Word 粘贴、部分预览器、
微信内置浏览器都不认，`<msup>` 直接退化成纯文本 `2`。

#### 修法
**上标改用 HTML `<sup>`**：
```python
return "%s<sup>%s</sup>" % (_esc(base), e) # 输出 (b−10)<sup>2</sup>
```
`<sup>` 是 HTML 基础标签，所有浏览器 / 编辑器 / 粘贴场景全认。

#### 分工原则（重要）
| 元素 | 用什么 | 理由 |
|:--|:--|:--|
| **分数** `<mfrac>` | MathML | 分数线居中、分子分母对齐，`<sup>` 无法替代 |
| **上标** | HTML `<sup>` | 兼容性最好，MathML 会退化 |
| 根号 | MathML `<msqrt>` | 需要上横线 |

> **教训**：**「标准最高级」不等于「最可靠」。**
> MathML 是 W3C 标准，但实际渲染环境（Word、微信、旧浏览器）支持不全。
> **能用基础 HTML 表达清楚的（上标/下标），就不要上 MathML。**

> ⚠️ **注意**：纯文本提取（`re.sub(r"<[^>]+>","")`）会剥掉 `<sup>` 标签，
> 看起来像 `10)2`。**这是提取的假象，浏览器渲染是对的** ——
> 判断上标有没有生效要看 HTML 源码，不要看剥完标签的文本。

### 5A.35 🔴 `s.find("<body>")` 匹配到 JS 字符串 → 整个页面变成纯文本（阶段22）

#### 症状（最严重的一次）
用户打开 Day3 讲义，**页面上只有一段 CSS 源码**：

```
/* 真分数竖式（阶段21 用户要求：不能写成斜杠 3/2，必须竖式） */
.fr{display:inline-flex;flex-direction:column;...}
```

整个页面没有任何内容，只有这段样式代码暴露出来。

#### 根因：截断点落在 `<script>` 中间

生成单日头时用了：
```python
i = s.find("<body>")
head = s[:i + 6]
```

但 `_p6/00_head.html` 的 `<script>` 里有个 JS 函数 `toWordHtml()`：

```javascript
function toWordHtml(title, bodyHtml){
  return '<html xmlns:o="..." ...><head><meta charset="utf-8">'
    + '<title>' + title + '</title>'
    + ...
    + '</style></head><body>' // ★ 这里也有 "<body>"
```

`s.find("<body>")` 找到的是**字符串里的这一处**（位置 26389），
而真正的 `<body>` 在 28000 之后。

于是截断点落在 `<script>` **中间**：
- `</script>` 被截掉
- `</head>` 被截掉
- 浏览器认为 `<script>` 一直没闭合 → 后面所有内容当脚本/文本
- 页面上只漏出一段 CSS

#### 修法
```python
pos = s.rfind("<body>") # 取最后一个 <body>，即真正的那个
```

#### 更重要的教训：**结构必须用解析器验，不能字符串计数**

`t.count("<head>")` 这种统计会被 JS 字符串里的同名标签干扰，
永远数不准。用 `html.parser` 走一遍：

```python
from html.parser import HTMLParser

class Struct(HTMLParser):
    def __init__(self):
        super().__init__(); self.seq = []
    def handle_starttag(self, tag, attrs):
        if tag in ("html", "head", "body"): self.seq.append(tag)
    def handle_endtag(self, tag):
        if tag in ("html", "head", "body"): self.seq.append("/" + tag)

p = Struct(); p.feed(html)
assert " ".join(p.seq) == "html head /head body /body /html"
```

> ⚠️ `HTMLParser` 会把 `<script>` 内容当 data，**不会**解析里面的标签 ——
> 这正是我们要的：只看真实 DOM 结构。

#### 自检清单（生成 HTML 后必做）
1. `html.parser` 走一遍，确认嵌套顺序
2. 确认 `<script>`/`</script>`、`<style>`/`</style>` 配平
3. **肉眼看文件开头 200 字**（应该是 `<!DOCTYPE html>` 而不是 CSS）

### 5A.39 数学概念必须**先给生活场景，再抽数学结构**（阶段22 用户）

用户：「这些数学概念在讲义中**最好要结合他们在生活和现实世界中应用**来讲解」

#### 三个反例（不要这么做）
- ❌ 上来就写 `｜x−a｜ 表示 x 到 a 的距离` —— 孩子只能背
- ❌ 讲完公式补一句"比如生活中的……" —— 那是装饰，不是讲解
- ❌ 用"几何意义""数形结合"这类词 —— 初一听不懂

#### 正确顺序：生活 → 结构 → 符号

```
① 先抛生活场景（孩子有经验、能立刻回答）
② 追问「为什么」（把场景压缩成一句话的道理）
③ 再抽出数学结构（这时符号才有意义）
```

**示例（绝对值最小值）**：
> ① 小区要在门口建一个快递柜，让所有楼栋的人走的总路程最短——建哪儿？
> ② 大家都会说"中间"，为什么？因为建在边上，最远那栋要多走一个来回。
> ③ 这就是 `｜x−a｜+｜x−b｜` 的最小值 = a 到 b 的距离，x 取中间。

#### 八个概念的生活锚点

| 概念 | 生活场景 | 一句话道理 |
|:--|:--|:--|
| ① 数轴方向 | 电梯楼层：地下 2 层是 −2，地上 5 层是 +5；温度计零下 3 度 | 上和下、冷和热，**方向相反就用正负分** |
| ② 绝对值 = 路程 | 打车：向东 3 公里和向西 3 公里，**车费一样** | 车费只看**走了多远**，不看朝哪走 |
| ③ `｜x−a｜` | 快递柜在 3 号楼，你住 5 号楼，要走 2 分钟 | 「离某处多远」写出来就是 `｜x−a｜` |
| ④ 两点距离 | 地铁从第 3 站到第 8 站，中间隔 5 站 | 不管从哪头数，**站数一样** |
| ⑤ 最小值 | **小区建快递柜**（或村庄建公交站）：建中间 | 建边上，最远那栋要多走一个来回 |
| ⑥ 动点位置 | 两个人从各自家相向走，几分钟后在哪碰面 | 起点 + 走的量；往左走就减 |
| ⑦ 距离 V 形 | 两人先靠近、擦肩而过、再拉开；**错过路口** | 同一段距离，去的时候一次、回来又一次 |
| ⑧ 到原点距离 | 记账：支出 20 和收入 20，**金额都是 20** | 收支方向相反，但数目一样大 |
| ⑨ `｜M｜=M` | 误差不超过 5 克 ⇒ 误差是正数或 0 | 一个数的绝对值等于它本身，这数就不能是负的 |

> 场景要选孩子真经历过的（电梯、打车、快递柜、地铁、记账），

### 5A.40 家长讲课用的「口播卡」教案格式（阶段22 用户：我自己来讲）

用户：「讲义要详细，**我自己来讲**，要保留我之前说的那些要求」
→ 澄清：「**我是指周六周日的数学**」

#### 定位差别
| | 孩子自学学案 | **家长讲课教案（口播卡）** |
|:--|:--|:--|
| 主语 | 你（孩子） | **我（家长）** |
| 内容 | 知识点 + 题 | **问句 + 讲法 + 预判** |
| 答案 | 可以附在题后 | **一律放最后**，讲完做完才翻 |

#### 每节固定六段
```
【讲完他应该能】一句话，可观测
【三个启发问句】先问，等他答，别急着讲
【底层逻辑】5 层，从生活到符号
【练习 + 判读】错在哪一步 = 哪个概念没懂
【常见错法】2-3 种，各配一句应对
【答案】集中放文末
```

#### 三个启发问句怎么写
必须**层层递进**，最后一句把他逼到"必须用数学解释"：
> ① 「两个点相向走，什么时候距离最近？」
> ② 「擦肩而过之后，距离会变近还是变远？」
> ③ 「如果我说'相距 8 米'，这件事可能发生几次？」← 这问直接指向漏解

#### 底层逻辑固定 5 层（不能少）
以「绝对值」为例：
1. **距离是什么**（生活定义）
2. **数轴上算距离会出负数**（问题出现）
3. **所以规定加绝对值**（为什么这么定义）
4. **`｜x｜` 是到原点的距离**（特例）
5. **`｜x−a｜` 是把 a 当新原点**（一般化）

> ⚠️ **最容易漏的是第 2 层** —— 直接说"绝对值就是距离"是**给结论**，
> 孩子不知道"为什么需要它"。必须有"减反了会得负"这个冲突。

#### 判读标准要写具体
不能写"错了就重讲"，要写清**错成什么样说明什么**：
> · 答 **6** → 懂了
> · 答 **2** → 算成了差的一半
> · 答 **12** → 两段各算了一遍，重复计数
> · 答「x=1 时最小」→ 以为只有一点取到，让他代 x=0、x=2

#### 答案必须自己验算（技能规则 9）
本轮 6 节练习全部手工验算：
第1节 0/3/4.5/−2、2、13；第3节 8或4、m=3；第4节 8/3或8；第5节 3或15；第6节 6、8。
**每一个都代回原式核过。**

### 5A.41 🔴 「点破式」讲解 —— 不能把学生当零基础（阶段22 用户）

用户：「要讲底层逻辑也**不能把学生当成什么都不会**，他已经学过了，
要给他们**更好的数学概念**，而不是从头开始讲，要给他一个**醍醐灌顶**的讲解。
周六周日的讲解都一样，这点要记录到技能中。」

#### 我犯的错
周教案里写「绝对值就是到原点的距离」「两点之间线段最短」——
**这些他课本上学过**。再讲一遍 = 浪费时间 + 他觉得"我懂了"然后走神。

#### 点破式 vs 教学式

| | 教学式（❌ 我之前写的） | **点破式（✅ 要的）** |
|:--|:--|:--|
| 起点 | 假设他不知道 | **确认他会，再往下推** |
| 内容 | 从定义讲到例题 | **指出他"以为懂了"的地方其实有坑** |
| 效果 | "哦，学过了" | **"原来是这样！"** |
| 收尾 | 会做题 | **回看：原来那些口诀都是这句话的特例** |

#### 四步结构（每节都按这个）
```
① 你说说，你现在是怎么做的？（让他讲他的方法，确认他会）
② 那我改一个条件呢？（他的方法崩了 —— 制造冲突）
③ 真正管用的是哪一句话？（给上层视角，一句顶十句）
④ 回头看：你原来背的那些，都是这句话的特例
```

#### 实例对比

**绝对值**
> ❌ 教学式：「绝对值表示一个数到原点的距离」
> ✅ 点破式：
> 「你现在算 `｜−5｜` 是不是'把负号去掉'？（他会说对）
> 那我问你：`｜3−8｜` 呢？先算 `3−8=−5`，再去负号得 5。
> 可如果题目是 `｜8−3｜` 呢？得 5。**同一个距离，减的顺序不同，结果一正一负。**
> 所以'去负号'只是**算法**，它背后那句话是'**量出隔了几格**'。
> 你以前记的是算法，今天记的是**它为什么成立**。」

**绝对值最小值**
> ❌ 教学式：「记住，两个绝对值相加，x 取中间最小」
> ✅ 点破式：
> 「考试遇到 `｜x−2｜+｜x−5｜`，你是不是直接答 3？（他会说对）
> 那 `｜x−2｜+｜x−5｜+｜x−8｜` 呢？'取中间'还管用吗？
> （他答不上来 —— 冲突产生）
> 管用，但**理由不是'取中间'**，是'**两段路能拼成整段就不绕路**'。
> 三个点时 x 落在 2 和 8 之间任何地方，距离和都是 6 —— 因为中间那个点 5 不影响。
> **你背的'取中间'，是这句话在两个点时的特例。**」

#### 纪律
1. **每节第一句必须是"你现在是怎么做的"**，不是"什么是……"
2. **必须制造一次冲突**（改个条件，让他的老方法失效）
3. **只给一句"真正管用的"**，不要一次给三条

### 5A.42 🔴 FILL 是 **6 段**，不是 5 段（阶段23 踩坑）

#### 事故
批量写了 21 道 FILL，全部报「题干过短「」」——**题干变成空字符串**。

#### 根因
正确格式是 **6 段**：
```
FILL|题干|答题格式|答案|提示|解析
```
我只写了 5 段（漏了第 3 个「答题格式」）。

解析器用「倒数字段法」（因为题干里可能含 `|`）：
```python
sol, hint, a3, a4 = p[-1], p[-2], p[-3], p[-4]
stem = "|".join(p[:-4])
```
5 段时 `p[:-4]` 是空列表 → **stem = ""**。

#### 修法
补第 3 个字段「答题格式」，按题目的问数自动选：
- 多问（含 ①②③ 或 （1）（2））→ 「格式：分条写，标清 ①②③，有几问写几问」
- 单问 → 「格式：写出答案，注意带单位（如有）」

#### 自检
写完 FILL 必须跑一次：
```python
import dsl_source as D
for d in D.load_days("_p5"):
    for q in d["qs"]:
        assert q["stem"].strip(), "第 %d 题题干为空" % q["no"]
```

> **MC 也是 6 段**：`MC|题干|答题格式|选项(用@分)|正确项序号|提示|解析`？不对——
> MC 是 `MC|题干|格式|选项|序号|提示|解析`。**反正记住：题干后面必须先有一个「格式」字段。**

### 5A.45 ✅ 已验证有效讲法（阶段23 用户实测，**不要改回去**）

需求原话：「**今天动点给学生讲明白了，尤其是相遇、相距的两解问题。**」

Day4 按「本质卡 + 五步法 + V 形图 + 变式筛解」讲，一次讲通，包括此前最容易漏的两解。
以后改版前先看这张表，**不要把这些设计优化掉**。

#### 起作用的六个设计

| # | 设计 | 为什么有效 |
|:--|:--|:--|
| 1 | **本质卡放最前**：把「时间」换算成「位置」 | 先给一句他能记住的话，后面每一步都是它的展开 |
| 2 | **小学比方**：每秒 1 米，10 秒后 10×1=10 米 | 接到他已有的乘法上，不觉得在学新东西 |
| 3 | **函数视角**：「你不是在做难题，是在提前摸函数」 | 给这件事一个「占便宜」的意义，不是苦差事 |
| 4 | **五步法**：设→写→表→列→验 | 把「没头绪」变成「照单办事」，每步都有动作 |
| 5 | **V 形图**：一条水平线穿过去必然两个交点 | 把「两个时刻」变成**看得见**的，不靠背「拆两行」 |
| 6 | 一句追问：**「追上了没有？」** | 把抽象的「分段讨论」变成一个他必须回答的具体问题 |
| 7 | **变式加条件筛解**（P 在 Q 右边，两个解只留一个）| 分水岭：从「会算」升到「会筛」 |

#### 🔴「两解」这次为什么能通（最关键的一条）

以前讲「绝对值等于正数要拆两行」——他只记住动作，**不知道什么时候该拆、为什么会有两个**。
这次走的是**几何路径，不是代数路径**：

> 距离随时间先减后增 → 画出来是 V → 水平线穿过去 → **必然两个交点** → 所以两个时刻

**不是「所以要拆两行」，是「所以一定有两个」。**
他知道为什么一定有两个，拆两行只是执行动作而已。

> **凡是「多解」类问题：先画那个会变的量（V 形 / 折线），再谈拆方程。**
> 顺序反过来，他只能背。

#### 可迁移方向

| 后续场景 | 怎么迁 |
|:--|:--|
| 绝对值最小值（Day5）| 同一条数轴上「位置→距离」，只是从「给定距离求时刻」翻成「让距离和最小」 |
| 到原点距离（Day4 下篇②）| 同一个「越不越过参照点」的分段判断 |
| 找规律（Day6）| 「变化量」先画出来再找规律，同一招 |
| 应用题偏差（Day8）| 先画柱状图看上下浮动，再谈正负 |

#### 纪律
1. 讲多解，**必须先有图**，再谈方程。
2. 「追上没有」「越过没有」这种**一句追问**，比讲三分钟原理管用 —— 它逼他做判断。
3. 变式题里**加一个筛选条件**，比多做三道同型题有用（这一步才是真区分）。

### 5A.46 🔴 做对了就要换考法 —— 三个变换维度（阶段24 用户）

用户：「今天的最值问题练习题**都做对了**，又复习了昨天的动点多值问题。
**周末的对这些题目的考察要有变化。**」

#### 原则
> 某一类题**全对之后，不能再出同型题**。同型题只会让他"手熟"，不会让他"更懂"。
> 下一步要**换考察方向**，逼他把同一句话反过来用。

#### 三个变换维度（按难度递增）

| 维度 | 从 | 变成 | 例子 |
|:--|:--|:--|:--|
| **① 正向 → 逆向** | 给点，求最小值 | 给最小值，求那个点 | ｜x−3｜+｜x−a｜ 最小值 8 → a = 11 或 −5 |
| **② 等式 → 范围** | = 8，求 x | ≤ 8，求解集/整数解个数 | ｜x−1｜+｜x−6｜ ≤ 8 → −0.5≤x≤7.5，8 个整数 |
| **③ 单阶段 → 多阶段** | 一条路走一遍 | 折返，一条路走两遍 | Day8 折返：去程+回程 × 两个位置 = 4 个解 |

#### 落地（阶段24 已做）
- **Day7 新增下篇②「最值的变化考法：反着问」**：逆向求参数 + 范围求整数解（2 题，配"一个点两个答案"的图）
- **Day8 下篇②「动点压轴：折返（四个解）」**（前面已做）：动点那一侧的变化

#### 出题纪律
1. 全对之后，**当天不加重同型题**；下一轮直接上变换维度① 或 ②。
2. 变换后**必须仍然只用他学过的那一句话推**（如"最小值就是两点距离"），
   不能引入新工具——否则考的是新知识，不是理解深度。
3. 每个变换维度**只出 1-2 题**，多了变成刷题。
4. 逆向题**答案通常是两个**（点可以在两边），这是最容易漏的地方，判读就看这一点。

### 5A.47 🔴 先摆「六种面孔」，再点破「一个动作」（阶段24 用户）

用户：「这种要**先列一些题型出来，比如错过的那些题**，然后来指出他们是要找规律。」

#### 为什么要这么排
直接讲「找规律要先算差」——他没感觉，因为不知道这句话管什么。
先把**同类题的不同面孔**摆一排，他的第一反应是「这些我都见过 / 这题我错过」，
**有了代入感，再点破共同点，冲击才成立。**

#### 操作模板（找规律这一节的实例）
```
① 数列 2、5、8、11、
② 符号交替 1、−2、3、−4、… 第 198 个？ ← 标「你错过这类」
③ 平方型 2、5、10、17、26、…
④ 图形 小棒摆正方形：4、7、10 根
⑤ 周期 珠子红黄蓝，第 100 颗什么色
⑥ 表格 每行每列同一差递增
```

1. **必须有一个是他真错过的**，标出来（「← 你错过这类」）。没有真错题就从学情报告里挑。
