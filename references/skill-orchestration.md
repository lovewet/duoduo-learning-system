# 技能编排规则（Skill Orchestration）

> **核心原则：学生学习系统是"总调度"，不是"全能选手"。**
> 每次出题、做讲义、推视频，都要**按固定序列调用已安装的学习类技能**，不能只凭本技能单打独斗。
> 版本：1.0　建立日期：阶段19

---

## 0. 可调用的学习类技能清单（本机已安装）

| 技能 | 擅长什么 | 什么时候必须叫它 |
|:--|:--|:--|
| **duoduo-learning-system** | 四库（错题/知识点/题库/掌握度）+ 排程 + 讲义流水线 | **每次都用**（先查库，最后入库） |
| **mingbian-error-attribution** | 初中数学错题归因（输入错解过程，输出"错在哪一步"） | **凡有学生错解**就要用它，不要自己凭感觉归因 |
| **mingbian-tiered-variation** | 初中数学双通道分层变式命题（A 复现 / B 变式 / C 迁移） | **凡出数学题**就要用它分层，避免难度一股脑 |
| **mingbian-paper-blueprint** | 初中数学组卷 + 双向细目表（考点×分值×难度） | **凡成卷 / 阶段测评**就要出细目表 |
| **study-methods-lookup** | 2000+ 学习方法与解题技巧检索（8 学科 16 学段） | **凡讲解 / 出题**都要配"方法卡"，不要自己编方法名 |
| **junior-school-portal** | 初中各科学习指导（概念讲解、例题示范、学科答疑） | **凡讲概念 / 补背景**就用它，保证学段口径 |
| **muma-learning-expert** | 初中物理/数学/化学自主学习（自带三科内容） | **理化内容**优先用它；数学可作交叉校验 |
| **socrates-math-coach** | 交互式数学实验（动点、函数图像、几何可视化） | **凡"动态/图形"知识点**（动点、函数、几何）用它生成可交互图 |
| **study-guide-html** | 单文件 HTML 讲义版式（五色提示框、可折叠、可打印） | **凡做讲义**参考它的版式规范，保证可直接打印 |

> 另有通用产出技能：`docx` / `pptx` / `xlsx` / `pdf` / `pdfkit-py` —— 需要导出 Word/PPT/PDF 时调用。

---

## 1. 三条铁律

### 铁律一：先查库，再动手
任何出题/讲义请求，**第一步必须是 `duoduo` 查库**：
- 这个知识点错了多少次？（`mastery.error_count`）
- 有没有出过同类题？（`questions` 查重，避免原题重出）
- 上次练习结果如何？（`practice_log`）

**不查库就出题 = 可能把做过的题再出一次，浪费孩子时间。**

### 铁律二：归因不自创，交给明辨
有学生的错解过程时，**先调 `mingbian-error-attribution`**，用它的归因框架；
`duoduo` 的 13 值 `error_type` 只做**入库字段**，不作为归因方法。

### 铁律三：方法名不编造，一律检索
讲义里的"方法卡"必须来自 `study-methods-lookup` 的检索结果，**不许凭记忆写方法名**。
检索不到就老实说"这一块方法库没有专条"，不要造一个像模像样的名字。

## 2. 出题的固定编排（4 步）

```
① duoduo 查库 → 该考点错几次、出过什么题、上次对不对
② mingbian-tiered-variation → 按 A/B/C 三层生成变式题
③ mingbian-paper-blueprint（成卷时）→ 双向细目表（考点 × 分值 × 难度）
④ study-methods-lookup → 给每道题配"方法提示"（只给方法，不给答案）
```

**输出内容必须包含**：
- 三层题各几道（A 复现 / B 变式 / C 迁移）
- 每题标注考点 + 难度
- 成卷时附双向细目表（哪个考点占几分）
- 查重结论（哪几道是新的、哪几道是变形）

**禁止**：一次性出 10 道同难度的题（那不叫分层，叫堆量）。

---

## 3. 做讲义的固定编排（5 步）

```
① duoduo → 定考点（按 mastery 排序，0 分优先）
② study-methods-lookup → 每节取 1 条对口方法（写明方法名 + 出处）
③ junior-school-portal → 补概念讲解与例题（保证学段口径）
④ socrates-math-coach → 凡"动态/图形"知识点，生成可交互/可视化图
⑤ study-guide-html → 版式规范（五色提示框、可折叠、可打印）
```

**讲义里必须能看到这五步的痕迹**：
- 「先说清楚」段落 = ③ 的产出
- 「📖 配套方法（来自你的学习方法库）· X 方法」= ② 的产出
- 程序框图 / 动点图 / 函数图像 = ④ 的产出
- 可打印的作答纸 = ⑤ 的版式规范
- 每题的 error_pattern = ① 的库

---

## 4. 视频推荐的固定编排（3 步）

```
① duoduo §8 规则 → 短视频优先（≤15 分钟）、单点、每节 2~3 条候选
② B 站 API 核实 → 每条都要查存在性 + 真实时长（/x/web-interface/view?bvid=）
③ junior-school-portal / socrates-math-coach → 交叉验证"这条是否对口"
```

**红线**：
- **没核实过的链接不能给**（会失效、会张冠李戴）
- **找不到对口的，如实说"建议在 B 站搜 XXX 关键词"**，不硬凑
- 每条必须标：首选 / 备选 + 时长 + 看哪一段

---

## 5. 错题归因的固定编排（3 步）

```
① mingbian-error-attribution → 输出"错在哪一步 / 属于哪类错"
② study-methods-lookup → 配一条对应的方法（治这类错的）
③ duoduo 入库 → error_type(13值) + error_pattern + student_steps + severity
```

**注意**：明辨擅长**初中数学**；语文/英语的归因走 `duoduo` 的三科分门规则 + `study-methods-lookup` 的方法。

---

## 6. 数学实验 / 可视化的编排（2 步）

```
① socrates-math-coach → 生成交互页面（动点、函数、几何变换）
② duoduo → 记录"该知识点曾用交互方式学过"，下次优先复用
```

**适用场景**：动点问题、函数图像、几何变换、最值问题——**凡是"动起来才看得懂"的**。

---

## 7. 技能调用的自检（每次交付前问自己 5 句）

1. **查库了吗？** 这个考点在库里的状态是什么？
2. **归因用明辨了吗？** 有错解时是不是自己拍脑袋写的？
3. **分层了吗？** 出的题是不是有 A/B/C 三档？
4. **方法卡是检来的吗？** 方法名能不能在 `study-methods-lookup` 里查到？
5. **视频核实了吗？** 每条 BV 号是不是都调过 API？

**五问有一问答"否"，就不要交付。**

---

## 8. 编排记录（写进讲义页脚）

讲义末尾应注明本次调用了哪些技能，例如：

```
本事讲义调用：duoduo-learning-system（四库+流水线）、study-methods-lookup（17 条方法）、
junior-school-portal（概念口径）、socrates-math-coach（动点可视化）、B站 API（19 条视频核实）
```

**这是可追溯性要求**：家长问"这些内容哪来的"，能一句话答清楚。

## 9. 择优规则：多源结果怎么选（阶段19 用户明确要求）

> **用户原话：「每次调用这些相关技能要对其方法和结果选取最优的最适合学生的来输出成果。」**
> 意思是：**不要把多个技能的产出堆在一起交差**，而要**筛选**——只把最匹配学生的那一条放进去，其余淘汰并记录理由。

### 9.1 择优四问（每条候选都要过一遍）

| # | 问什么 | 不合格就淘汰 |
|:--|:--|:--|
| ① | **能对上他的哪个 error_pattern？** | 说不出对应哪条错因的，淘汰（泛泛而谈的不要） |
| ② | **难度在他「跳一跳够得着」的区间吗？** | 他 mastery 已 3 级的（会了）不要；需要先补前置知识的也不要 |
| ③ | **他能独立完成吗？** | 必须家长全程讲解才做得出的，淘汰（这不是他的任务，是家长的任务） |
| ④ | **做完能判断对错吗？** | 答案不唯一、标准模糊的，淘汰（无法批改 = 无法闭环） |

**四问全过才入选；有一条不过就淘汰。**

### 9.2 各类产出的淘汰清单

#### 方法卡（`study-methods-lookup` 可能返回多条）
- ❌ 淘汰：需要先补前置知识的（如"待定系数法"要用到方程，他方程还没学透）
- ❌ 淘汰：抽象到无法落地的（"运用数形结合思想"——这句话本身不是动作）
- ❌ 淘汰：方法名唬人但步骤超过 5 步的（他记不住）
- ✅ 优选：**有明确 1-2-3 步骤**、**能当场用在这道题上**的
- ✅ 优选：**针对他这类错因**的（他错在"分类不穷尽"，就选"分类讨论法"，不选"整体代入"）

#### 讲解（`junior-school-portal` / `muma-learning-expert` 口径可能不同）
- ❌ 淘汰：术语密度过高的（一上来就"非负性""恒等变形"）
- ❌ 淘汰：举例超出他生活经验的（用"股票涨跌"讲负数，不如"电梯楼层"）
- ❌ 淘汰：和他教材版本口径冲突的（以他用的教材为准）
- ✅ 优选：**从"他为什么会错"切入**的讲法，不是从"知识定义"切入
- ✅ 优选：**带一个完整演算演示**的（讲完能照着走一遍）

#### 题目（`mingbian-tiered-variation` 生成 A/B/C 三层，不是全用）
- ❌ 淘汰：**他做过的原题**（查 `questions` 表确认）
- ❌ 淘汰：难度跳跃过大的（A 直接跳 C，中间没有 B 过渡）
- ❌ 淘汰：答案不唯一的（没法批改）
- ✅ 优选：**命中他 error_pattern 的变形**（他错在"漏第二种情况"，就专门给一道"必有两解"的）
- ✅ 优选：**每天 A/B/C 各 1 道**，不搞 10 道同难度

#### 视频（`B 站 API` 会返回多条候选）
- ❌ 淘汰：超过 20 分钟的（他坐不住）
- ❌ 淘汰：讲竞赛技巧 / 超前内容的
- ❌ 淘汰：标题党、画质音质差的
- ❌ 淘汰：**核实不到 BV 号的**（不能给可能失效的链接）
- ✅ 优选：**单点短视频（3~8 分钟）**、**标题就是这个概念**、**播放量过万**
- ✅ 优选：**每节 2~3 条**，标清"首选 / 备选"，说明"看哪一段"

#### 归因（`mingbian-error-attribution` 可能给多个可能原因）
- ✅ 优选：**置信度最高**的那一条作主因
- ✅ 保留：次要原因写进 `error_pattern` 的补充说明，但**不要平铺成并列**
- ❌ 淘汰："粗心""不认真"这类**不可操作的归因**（不可操作 = 不可改）

### 9.3 择优记录（可追溯）

讲义/题目交付时，附一行**择优说明**，例如：

```
【择优】方法卡：从 5 条候选中选「分类讨论法」——因为他的 error_pattern 是"距离只写一解"，
其余 4 条（整体代入 / 裂项 / 分配律 / 非负性）与本错因不对应，未采用。
题目：A 层 1 道（复现）+ B 层 2 道（变形，命中"两解"）+ C 层 1 道（动点综合）。
视频：3 条候选中选 2 条，淘汰 1 条 37 分钟的（超时）。
```

**为什么要有这一行**：家长问"为什么选这个"，能一句话答清楚；下次复用也知道当时的判断依据。

### 9.4 一条底线

**宁可少给，不要凑数。**
- 方法库查不到对口的 → 说"这一块没有专条"，不硬套一个
- 视频找不到短的 → 给搜索关键词，不硬塞一条不相干的
- 题目凑不够 4 道 → 就出 3 道，不拿"难度不对"的题填数

**凑数的内容会稀释真正有用的内容**——这是本技能最容易犯、也最伤信任的错误。
